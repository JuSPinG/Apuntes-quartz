58. Comprobación del ejercicio extra sobre `/etc/fstab`.
	1. ![[Pasted image 20260420120236.png]]
	2. ¿Por qué es tan importante dar establecer los permisos en las particiones? Es una forma extra de proteger el sistema. Con `nodev`, prohibimos que se interpreten dispositivos en las particiones `/home`, `/tmp`, `/boot`, `/var/log` y `/var/log/audit`. Con `nosuid` se garantiza que los programas ejecutados no ignoren el identificador del usuario (que lo marca como administrador o no), y aplica a `/home`, `/tmp`,  `/boot`, `/var/log` y `/var/log/audit`. Con `noexec` establecemos que sea imposible ejecutar archivos en las particiones `/tmp`, `/boot`, `/var/log` y `/var/log/audit`. Por último, la bandera `ro` establece que la partición será solo de lectura (_read only_), se aplica a `/boot`, lo que propiciará que tenga que montarse con permisos de lectura para recargar el _kernel_.

## Máquina de Difusión Limitada

1. Incidente: Aparecen mensajes extraños por la terminal tras ejecutar `apt`.
	1. Evidencia:

2. Incidente: La configuración de las directivas de contraseña (`CCN-STIC-610_Directivas_de_credenciales.sh`) no se aplica correctamente (otra vez).****^1
	1. Evidencia: 
	   ```sh
	   $ md5sum pwquality.conf*
	   679fa78b6ec12124527154c556af807c  pwquality.conf
	   679fa78b6ec12124527154c556af807c  pwquality.conf.bak_2026-04-15
	   ```
	   En otras palabras, hace una copia pero no modifica nada, cuando es evidente que el _script_ debería propiciarlo.
	2. Causa raíz: La búsqueda y sustitución que hace con `sed` es peliaguda, ya que no hace las comprobaciones necesarias. En el fragmento:
	   ```sh
	   echo "[+] Aplicando configuracion de seguridad de contrase as..."
	   AUTH_CONF="/etc/security/pwquality.conf"
	   
	   echo "[+] Editando $AUTH_CONF..."
	   cp -a "$AUTH_CONF" "${AUTH_CONF}.bak_$(date +%F)" 2>/dev/null || true
	   
	   sed -i "s/^#*minlen.*/minlen = $MIN_LEN/" "$AUTH_CONF"
	   sed -i "s/^#*dcredit.*/dcredit = -$MIN_DIGIT/" "$AUTH_CONF"
	   sed -i "s/^#*ucredit.*/ucredit = -$MIN_UPPER/" "$AUTH_CONF"
	   sed -i "s/^#*lcredit.*/lcredit = -$MIN_LOWER/" "$AUTH_CONF"
	   sed -i "s/^#*ocredit.*/ocredit = -$MIN_SPECIAL/" "$AUTH_CONF"
	   ```
	   La búsqueda `^#*minlen` (y en general todas las búsquedas) falla, pues el patrón `#*` espera entre $0$ y $X$ caracteres de "#", lo encuentra, pero luego no cuenta con el espacio, por lo que no sustituye nada
	3. Solución: Cambiar todos los`^#*` por `^#*[[:space:]]*`. O simplemente escribir a mano:
	   ```sh
	   minlen = 14
	   dcredit = -1
	   ucredit = -1
	   lcredit = -1
	   ocredit = -1
	   ```
	   En el archivo `/etc/security/pwquality.conf`. ^34c3ab
3. Incidente: El _script_ de `CCN-STIC-610_Bloqueo_de_cuentas.sh` no encuentra el directorio `/run/faillock`.
	1. Evidencia:

	   faillock: Error reading tally directory: No such file or directory

	2. Causa raíz: Imagino que en RHEL sí existe, pero en Ubuntu 24.04 no aparece.
	3. Solución: Se debe ejecutar `sudo mkdir -p /run/faillock/` en la terminal antes de ejecutar el _script_. El nuevo directorio se llenará con un archivo.

# Función para imprimir resultados y sumar contadores
print_result() {
    local status=$1
    local message=$2
    if [ "$status" -eq 0 ]; then
        echo -e "  ${GREEN}[OK]${NC} $message"
        ((PASS++))
    else
        echo -e "  ${RED}[ERROR]${NC} $message"
        ((FAIL++))
    fi
}

# Verifica si un servicio está activo
check_service() {
    local service=$1
    local desc=$2
    systemctl is-active --quiet "$service"
    print_result $? "$desc (Servicio: $service)"
}

# Verifica si un archivo contiene una expresión regular específica
check_file_regex() {
    local file=$1
    local regex=$2
    local desc=$3
    if [ ! -f "$file" ]; then
        print_result 1 "$desc - ARCHIVO NO ENCONTRADO: $file"
        return
    fi
    grep -E -q "$regex" "$file"
    print_result $? "$desc"
}

# Verifica si el output de un comando contiene una expresión regular
check_cmd_output() {
    local cmd=$1
    local regex=$2
    local desc=$3
    eval "$cmd" 2>/dev/null | grep -E -q "$regex"
    print_result $? "$desc"
}

check_ufw_port() {
    local port=$1
    local desc=$2
    
    # Esta regex busca el puerto al principio de la línea, seguido de /tcp o espacio,
    # y verifica que en esa misma línea exista ALLOW o LIMIT
    eval ufw status | grep -iE "^$port(/tcp)?\s+.*(ALLOW|LIMIT)" > /dev/null;
    print_result $? "$desc"
}

# Función para verificar servicios que deben estar desactivados o no existir
check_disabled_service() {
    local service=$1
    local desc=$2
    local status
    
    # Comprobamos si el archivo del servicio existe
    if ! systemctl list-unit-files | grep -qw "${service}.service"; then
        status="not-found"
    else
        # Obtenemos el estado, tomamos solo la primera línea y la primera palabra
        # Esto elimina el error de "masked disabled" duplicado
        status=$(systemctl is-enabled "$service" 2>/dev/null | head -n 1 | awk '{print $1}')
        
        # Si por algún motivo sale vacío (pero existe), asumimos que está disabled
        if [ -z "$status" ]; then status="disabled"; fi
    fi

    # Validación final
    if [[ "$status" == "masked" || "$status" == "not-found" ]]; then
        echo -e "  ${GREEN}[OK]${NC} $desc (Estado: $status)${NC}"
        ((PASS++))
    else
        echo -e "  ${RED}[ERROR]${NC} $desc requiere atención (Estado: $status)${NC}"
        echo -e "${YELLOW}      Tip: Use 'sudo systemctl mask --now $service'${NC}"
        ((FAIL++))
    fi
}
