# Directa

Cuando iniciemos Bind9, lo primero que tendremos que hacer es dirigirnos a la ruta `/etc/bind` para modificar el archivo `named.conf.local`. Añadiendo ahí mismo nuestra nueva zona:

```sh
$ cat /etc/bind/named.conf.local

zone "pruebas.com" IN {
	type master;
    file "/etc/bind/pruebas.com.zone";
};
```

Y nuestro siguiente archivo debe ser, por lo tanto, `"/etc/bind/pruebas.com.zone"`. Puede ser generado fácilmente mediante la copia de `db.local`, aunque será necesario también cambiar ciertos parámetros.

```sh
$ cat /etc/bind/named.conf.local

;
; BIND data file for local loopback interface
;
$TTL	604800
@	IN	SOA	pruebas.com. root.pruebas.com. (
			      2		; Serial
			 604800		; Refresh
			  86400		; Retry
			2419200		; Expire
			 604800 )	; Negative Cache TTL
;
@	IN	NS	ns1.pruebas.com.
ns1	IN	A	10.0.149.2
ns1	IN	AAAA	::1
```

De aquí sale una pregunta fundamental, ¿Por qué se usa el "@"? El "@" es un alias al nombre del dominio declarado en el archivo `named.conf.local`, en este caso, "pruebas.com".

Para recargar la configuración, y revisar que todo esté correcto, recomiendo usar el siguiente comando:

```sh
sudo systemctl restart bind9 && sudo systemctl status bind9
```

Uno puede comprobar que la configuración funciona cuando ejecuta lo siguiente:


# Inversa

Para configurar una zona inversa, debemos de repetir el procedimiento, añadiéndola así a `named.conf.local`.

```sh
$ cat /etc/bind/named.conf.local

...
zone "149.0.10.in-addr.arpa" IN {
	type master;
	file "/etc/bind/149.0.10.in-addr.arpa.zone";
};

```

Y esto haremos con el nuevo archivo:

```sh
$ cat 149.0.10.in-addr.arpa.zone 

$TTL    604800
@       IN      SOA     ns1.pruebas.com. root.pruebas.com. (
                              2         ; Serial
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL
;

@       IN      PTR     ns1.pruebas.com.
2       IN      PTR     ns1.pruebas.com.
```

# Subzona

Facilito, se recomienda usar la directiva `$ORIGIN` para ordenar dónde empieza la zona:

```sh
$ cat pruebas.com.zone 

$TTL    604800
@       IN      SOA     ns1.pruebas.com. root.pruebas.com. (
                              2         ; Serial
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL
;
@               IN      NS      ns1.pruebas.com.
ns1             IN      A       10.0.149.2
ns1             IN      AAAA    ::1
servidor1       IN      A       10.0.149.100

$ORIGIN subpruebas.pruebas.com

mail            IN      MX      10 servidor1.pruebas.com.
```
# Delegar

```sh
$ cat pruebas.com.zone

...
$ORIGIN delegado.pruebas.com.zone

@                     IN     NS       ns2.pruebas.com.
ns2.pruebas.com       IN      A       10.0.149.1
```

Esto por parte del servidor original que posee la zona, ahora, será necesario irse al servidor `ns2` y crear el siguiente archivo:

```sh
$ cat delegado.pruebas.com.zone

$TTL    604800
@       IN      SOA     ns2.pruebas.com mspineiro.asir21.asir. (
                       20251009         ; Serial
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL

@        IN      NS      ns2.pruebas.com.
```
# Reenvío

```sh
$ cat named.conf.local 

zone "google.com" {
    type forward;
    forwarders { 
        172.16.5.67; 
    };
};
```

Así, reenviará las peticiones que se hagan a Google a una dirección muy específica. Si queremos reenviar tramas de forma genera, debemos tener así el archivo `named.conf.options`:

```sh
$ cat named.conf.options 
options {
	directory "/var/cache/bind";
	
	 forwarders {
		172.16.5.65;
		// 8.8.8.8; // Así se añaden más IPs
	};
	
	// forward only; // Puede ser necesario si se quiere que reenvíe directamente si no encuentra una configuración local
};
```
