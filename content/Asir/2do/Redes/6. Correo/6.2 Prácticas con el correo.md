# Práctica 0: Instalando postfix

Lo primero de todo, tendremos que instalar las `net-tools` con `sudo apt install net-tools`. Y luego ejecutamos:

```sh
netstat -plnt
```

Hay que intentar que el puerto 25 no se utilice en ningún momento, pues es que utilizaremos para el servidor de correo. Así lo instalaremos:

```sh
sudo apt install postfix
```

Elegiremos servidor de uso local, y especificaremos el nombre de dominio `BOOKWORM21A.asir21.asir`. A continuación, ya se habrá instalado el sistema. Veamos si se ha iniciado:


Si queremos ver sus _logs_, usaremos:

```sh

```

Su archivo de configuración se encuentra en `/etc/postfix/main.cf`. En este archivo podemos encontrar las directivas `myhostname`, que ya hemos configurado antes, y `myorigin` es donde se guardan los correos.

Por otro lado, tendremos un apartado de `/etc/aliases` que será necesario guardar con:

```
# See man 5 aliases for format

root: alumno
```

Además, con `postconf` podemos añadir nuevas configuraciones.

# Práctica 2: Dominios y alias

Añadiremos esto a nuestro archivo de configuración:

```cnf
virtual_alias_domains = virtuallocal.asir21.asir
```

Todavía no sabe a quién enviar el correo, pero al menos no lo deniega automáticamente. Ahora hace falta direccionar:

```cnf
virtual_alias_maps = hash:/etc/postfix/virtual
```

Cuyo contenido será:

```
alumno@virtuallocal.asir21.asir alumno
usuariovirtuallocal@virtuallocal.asir21.asir alumno
```

Y ahora escribimos en la terminal:

```sh
sudo postmap /etc/postfix/virtual
sudo postfix reload
```

# Práctica 3: Dominios virtuales

Lo primero de todo, mantendremos las directivas de:

```conf
virtual_mailbox_domains = virtualnolocal.asir21.asir
virtual_mailbox_maps = hash:/etc/postfix/vmailbox
```

El contenido de este último archivo será:

```conf
virtualnolocal@virtualnolocal.asir21.asir virtualnolocal.asir21.asir/virtual/
```

Es decir, indicamos que no rechace automáticamente correos de esa dirección y especificamos a dónde hay que mandarlos. Además, especificaremos el directorio donde se guardarán estos correos a usuarios virtuales:

```conf
virtual_mailbox_base = /var/mail/vhosts
```

Aplicamos esta política de seguridad para que los administradores no toquen los correos:

```conf
virtual_minimum_uid = 100
```

Por último, especificamos el UID y el GID del usuario virtual que accede a dicho correo:

```conf
virtual_uid_maps = static:5000
virtual_gid_maps = static:5000
```

Ahora dejamos el archivo de configuración y escribimos lo siguiente en la terminal:

```sh
sudo mkdir -p /var/mail/vhosts/virtualnolocal.asir21.asir
sudo groupadd -g 5000 vmail
sudo useradd -g vmail -u 5000 vmail -d /var/mail/vhosts -m
sudo chown -R vmail:vmail /var/mail/vhosts
sudo systemctl restart postfix
sudo postmap /etc/postfix/vmailbox
```

# Práctica 4: Uso de dovecot

## Configurando dovecot

Lo primero de todo, es necesario como buena práctica la adición de registros DNS:

```
ftp                             IN   CNAME      bookworm21a
imap                            IN   CNAME      bookworm21a
stmp                            IN   CNAME      bookworm21a
virtualnolocal                  IN      MX      10 bookworm21a
virtuallocal                    IN      MX      10 bookworm21a
bookworm21a                     IN      MX      10 bookworm21a
```

Y ahora instalamos Dovecot en el servidor A con:

```sh
sudo apt install dovecot-imapd
```

Su archivo de configuración es `/etc/dovecot/dovecot.conf`. Otras configuraciones específicas se pueden encontrar en `/etc/dovecot/conf.d/`. Concretamente, entraremos en `/etc/dovecot/conf.d/10-auth.conf` para especificar:

```conf
auth_mechanisms = plain
```

Y en el mismo archivo, comentamos la línea:

```conf
!include auth-system.conf.ext # con un "#" delante
```

Y descomentamos esta:

```conf
!include auth-passwdfile.conf.ext
```

También sustituimos el contenido de nuestro archivo `/etc/dovecot/conf.d/auth-passwdfile.conf.ext` por:

```toml
passdb {
  driver = passwd-file
  # Aquí decimos qué archivo tiene las contraseñas
  args = scheme=plain username_format=%n /etc/dovecot/virtualnolocal.asir21.asir.passwd
}

userdb {
  driver = passwd-file
  # Aquí decimos dónde se guardarán los correos.
  # %d es el dominio y %n el nombre de usuario.
  args = username_format=%n /etc/dovecot/virtualnolocal.asir21.asir.passwd
  
  # Importante: Definimos que todos los correos virtuales pertenecerán 
  # al usuario real 'vmail' de Linux para no tener problemas de permisos.
  default_fields = uid=vmail gid=vmail home=/var/mail/vhosts/%d/%n
}
```

Y ahora deberemos crear el archivo de contraseñas (`/etc/dovecot/virtualnolocal.asir21.asir.passwd`)

```
virtualnolocal:{plain}123456::
```

Y ahora recargamos `dovecot`. Si nos conectamos (`telnet 127.0.0.1 143`), debería de no darnos error. Nos podemos logear con:

```telnet
A1 login virtualnolocal@virtualnolocal.asir21.asir 123456
```
```
A1 OK [CAPABILITY IMAP4rev1 SASL-IR LOGIN-REFERRALS ID ENABLE IDLE SORT SORT=DISPLAY THREAD=REFERENCES THREAD=REFS THREAD=ORDEREDSUBJECT MULTIAPPEND URL-PARTIAL CATENATE UNSELECT CHILDREN NAMESPACE UIDPLUS LIST-EXTENDED I18NLEVEL=1 CONDSTORE QRESYNC ESEARCH ESORT SEARCHRES WITHIN CONTEXT=SEARCH LIST-STATUS BINARY MOVE SNIPPET=FUZZY PREVIEW=FUZZY PREVIEW STATUS=SIZE SAVEDATE LITERAL+ NOTIFY SPECIAL-USE] Logged in
```

Cambiaremos el archivo de configuración `etc/dovecot/conf.d/10-mail.conf` para que pille los correos de otro lugar:

```conf
mail_location = maildir:~/Maildir
```

Y también cambiaremos en `/etc/dovecot/conf.d/10-auth.conf`:

```
disable_plaintext_auth = no
```

## Configurando postfix

Ahora editaremos el archivo `/etc/postfix/main.cf`:

```conf
mynetworks = 127.0.0.0/8 [::ffff:127.0.0.0]/104 [::1]/128 10.0.149.0/24
inet_interfaces = all
virtual_mailbox_domains = virtualnolocal.asir21.asir
virtual_mailbox_maps = hash:/etc/postfix/vmailbox
```

# Práctica 6: SMTP como _relay_ de correo

Eliminamos:

```conf
mynetworks = 127.0.0.0/8 [::ffff:127.0.0.0]/104 [::1]/128 10.0.149.0/24
```

De `/etc/postfix/main.cf`, y lo cambiamos por:

```conf
mynetworks = 127.0.0.0/8 [::ffff:127.0.0.0]/104
smtpd_sasl_type = dovecot
smtpd_sasl_path = private/auth
smtpd_sasl_auth_enable = yes
```

Así, Postfix ya no confiará de forma predeterminada en nuestra propia red. Ahora gestionaremos la autenticación mediante un socket de Dovecot. Editamos el archivo `/etc/dovecot/conf.d/10-master.conf` para ello, y escribimos en el apartado de `service auth`:

```conf
  # Postfix smtp-auth
  unix_listener /var/spool/postfix/private/auth {
    mode = 0660
    user = postfix
    group = postfix
  }
```

Y luego modificaremos el `/etc/dovecot/conf.d/10-auth.conf` y escribiremos:

```conf
auth_mechanisms = plain login
disable_plaintext_auth = no
```

Para comprobar que está todo correcto, escribimos esto en la terminal del servidor:

```sh
telnet 127.0.0.1 25
```

Y si vemos un:

```sh
250-AUTH PLAIN LOGIN
```

Entonces, está bien configurado. Ahora es necesario autentificarse, lo que es un poco raro porque a partir de ahora la comunicación debe hacerse en Base64. Este es un ejemplo de mi conexión:

```sh
$ telnet 127.0.0.1 25
Trying 127.0.0.1...
Connected to 127.0.0.1.
Escape character is '^]'.
220 bookworm21a ESMTP Postfix (Debian/GNU)
AUTH LOGIN
334 VXNlcm5hbWU6
dmlydHVhbG5vbG9jYWxAdmlydHVhbG5vbG9jYWwuYXNpcjIxLmFzaXI=
334 UGFzc3dvcmQ6
MTIzNDU2
235 2.7.0 Authentication successful
```

El `AUTH LOGIN` debemos escribirlo nosotros. A lo que nos responderán con `Username:` si estuviese codificado normal. Nosotros enviamos nuestras credenciales en la misma codificación, lo que equivale a `virtualnolocal@virtualnolocal.asir21.asir` y en el campo de la contraseña a `123456`.

# Añadiendo otro usuario

Tras todo lo que hemos llegado a configurar, puede ser confuso intentar crear otro usuario. Sin embargo, esta configuración suple la de las prácticas [[#Práctica 4 Uso de dovecot|4]], [[#Práctica 5 Usando SSL|5]] y [[#Práctica 6 SMTP como _relay_ de correo|6]]. En este ejemplo, añadiremos a "pepe", cuya contraseña es "123456".

Entramos en el archivo `/etc/dovecot/virtualnolocal.asir21.asir.passwd`, y añadimos:

```conf
pepe:{plain}123456::
```

Ahora definimos su carpeta. Para ello, modificamos el archivo `/etc/postfix/vmailbox`:

```conf
pepe@virtualnolocal.asir21.asir virtualnolocal.asir21.asir/virtual/
```

Reconstruimos el _hashmap_ con y recargamos con:

```
sudo postmap /etc/postfix/vmailbox
sudo systemctl reload postfix
sudo systemctl reload dovecot
```
