# Descripción de las máquinas virtuales

1. [ ] El escenario está formado por 6 máquinas virtuales que se alojan en las máquina anfitrionas de cada miembro del grupo.
2. [ ] Trabajo en el dominio 'desafioG.asir.', donde $G\in\{1,2,3,4,5,6\}$, que dependerá del grupo del que formes parte
3. [ ] Cliente LUBUNTU**G** (máquina similar a LINUXXX):
	1. [ ] Adaptador de red en modo red interna y DHCP (enp0s3)
	2. [ ] El adaptador anterior comenzará siendo un adaptador en modo NAT para poder descargar los paquetes que se necesiten y después se convertirá en un adaptador en modo red interna
4. [ ] Cliente WINDOWS**G**
	1. [ ] Adaptador de red en modo red interna y DHCP
	2. [ ] El adaptador anterior comenzará siendo un adaptador en modo NAT para poder descargar los paquetes que se necesiten y después se convertirá en un adaptador en modo red interna
5. [ ] Rúter: DEBIANROUTER**G**    
	1. [ ] Función de rúter activada
	2. [ ] NAT basado en puerto con sobrecarga (como se hacía el curso pasado en CISCO)
	3. [ ] DHCP Relay del ISC. Las peticiones le llegarán por la interfaz enp0s8 y se reenviarán por la interfaz enp0s3
	4. [ ] Configuración de red:
		1. [ ] Adaptador de red interna (inside): 172.18.1G.254/24 - enp0s8
		2. [ ] Adaptador de red en modo puente en la DMZ (outside): 172.18.G.4/24 - enp0s3
		3. [ ] Gateway en 172.18.G.254
		4. [ ] DNS 172.18.G.2
6. [ ] Servidor DHCP basado en KEA: DEBIANDHCP**G**
	1. [ ] Configuración de servicio DHCP para servir configuración de red a los equipos que están en la red local (interna): 172.18.1G.0/24
		1. [ ] Pool de direcciones entre la 101 y la 110
		2. [ ] Servidor DNS 172.18.G.2
		3. [ ] Puerta de enlace 172.18.1G.254
		4. [ ] Dominio: 'desafioG.asir'
	2. [ ] El servidor DHCP debe poder hacer actualizaciones dinámicas en el servidor DNS
	3. [ ] Configuración de red
		1. [ ] Adaptador de red DMZ en modo puente en la DMZ: 172.18.G.1/24
		2. [ ] Gateway 172.18.G.254
		3. [ ] DNS 172.18.G.2
7. [ ] Servidor DNS: DEBIANDNS**G**
	1. [ ] Servidor DNS basado en BIND9
	2. [ ] Configuración de servicio DNS:
		1. [ ] Zona maestra 'desafioG.asir.' con registros:
			1. [ ] NS: debiandnsG
			2. [ ] A: debiandnsG, debiandhcpG, debianwebG
			3. [ ] CNAME: www se traduce por debianwebG
    3. [ ] Se permiten actualizaciones dinámicas por parte del servidor DHCP, es decir, automáticamente el servidor DHCP perdirá que se creen los regitros A para los clientes a los que le sirva la configuración de red.
    4. [ ] El servidor DNS se configurará con reenvío al servidor 172.16.5.65
    5. [ ] Configuración de red:
        1. [ ] Adaptador de red DMZ en modo puente: 172.18.G.2/24
        2. [ ] Gateway 172.18.G.254
        3. [ ] DNS la propia máquina
8. [ ] Servidor Web: DEBIANWEB**G**
    1. [x] Servicio Web basado en Apache.
	    1. [x] Añadirme al `sudoers file`.
	    2. [x] Cambiar el `sources list`.
	    3. [x] `sudo apt install apache2`.
    2. [x] Configuración de red.
	    1. [x] Adaptador de red DMZ en modo puente: `172.18.G.3/24`.
	    2. [x] Gateway `172.18.G.254`.
	    3. [x] DNS `172.18.G.2`.
    3. [ ] Se servirá la aplicación STORK que permite interaccionar con servidores DHCP de Kea y DNS de BIND9 en la URL 'https://www.desafioG.asir/' configurando para ello un sitio virtual de Apache. El servicio STORK incluirá autenticación y al menos, poder ver las concesiones de direcciones realizadas por el servidor Kea e información sobre el servidor DNS.
	    1. [x] Instalando STORK.
		    1. [x] `sudo apt install curl`.
		    2. [x] `curl -1sLf 'https://dl.cloudsmith.io/public/isc/stork/cfg/setup/bash.deb.sh' | sudo bash`.
		    3. [x] `sudo apt install isc-stork-server`.
		2. [x] Configurando la conexión HTTPS.
			1. [x] Añadir la resolución interna (temporal hasta que haya conexión con el DNS): En `/etc/hosts` el contenido: `127.0.0.1 desafio3.asir`.
			2. [x] Añadir los complementos de Apache: `sudo a2enmod ssl proxy proxy_http headers`.
			3. [x] Establecer la configuración típica. Esto da fallo porque STORK no está completamente configurado:
			    ```xml
				...
					ServerAdmin webmaster@localhost
					ServerName www.desafio3.asir
					ServerAlias desafio3.asir
					DocumentRoot /var/www/desafio3
					# Proxy Inverso para STORK
					ProxyPreserveHost On
					ProxyRequests Off
					# El servidor STORK se ejecuta por defecto en el puerto 8080
					ProxyPass / http://127.0.0.1:8080/
					ProxyPassReverse / http://127.0.0.1:8080/
				...
				```
		3. [x] Creando la base de datos para STORK, se conecta como si fuese MySQL o una base de datos normal.
			1. [x] Igualmente, hay que añadir datos como:
			    ```
				STORK_DATABASE_HOST=localhost
				STORK_DATABASE_PORT=5432
				STORK_DATABASE_NAME=stork_db
				STORK_DATABASE_USER_NAME=stork
				STORK_DATABASE_PASSWORD=232425
				```
