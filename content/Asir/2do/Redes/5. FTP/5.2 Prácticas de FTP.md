# Práctica 0: Instalando y revisando configuraciones

Usaremos `vsftpd`, y lo instalamos con:

```sh
sudo apt install vsftpd
```

Toda la configuración se guarda en `/etc/vsftpd.conf`.

Tras acceder, introducimos nuestras credenciales de usuario del servidor. Si introducimos credenciales correctas, podemos incluso acceder, de forma predeterminada, a la raíz.

En cambio, si no introducimos credenciales, y entramos con el usuario "`anonymous`", no nos debería dejar entrar, por lo que vamos a habilitar esta opción.
## Habilitando al usuario anónimo

Para activar la configuración del usuario anónimo, habilitamos lo siguiente en el archivo de configuración:

```conf
# Allow anonymous FTP? (Disabled by default).
anonymous_enable=YES
```

La configuración anónima requiere que se active una carpeta para dichos usuarios. Esta se puede encontrar en `/srv/ftp`. El cliente, que se puede conectar usando la credencial de "anonymus" para el nombre, y el campo en blanco para la contraseña. Este se podrá descargar los ficheros del servidor usando el comando `get`:

```ftp
get fichero1.txt fichero1_descargado.txt
```

El primer parámetro es el nombre del archivo a descargar, y el segundo especifica cómo se debe llamar en la máquina cuando se descargue. Podemos ver que el archivo se encuentra en la máquina si ejecutamos el comando `!ls`. El `!` especifica que el comando se ejecute en la terminal local en vez de en el servicio ftp. También podemos subir un archivo descargado, usando el comando `put`:

```ftp
put fichero1_descargado.txt fichero1_subido.txt
```

Esto no funcionará porque el usuario anónimo, de forma predeterminada, no puede subir archivos. Esto se puede cambiar en la configuración, especificando `anon_upload_enable=YES` y el `write_enable=YES`:

```ftp
150 Ok to send data.
     0        0.00 KiB/s 
226 Transfer complete.
```

Es necesario, primero, darle permisos a la carpeta, yo he usado `chmod 775`. Para que los archivos recién subidos se puedan manejar más tarde, es necesario controlar los permisos. Con la directiva `local_umask=022` especificamos la máscara general para los archivos nuevos.

Por otro lado, si le queremos dar más libertad al usuario anónimo, la directiva `anon_other_write_enable` le permite al usuario anónimo modificar los archivos de otros usuarios. Y por último, uno puede especificar gracias a la directiva `anon_root` que el usuario anónimo posea una ruta distinta.

# Práctica 2: Gestión de usuarios

Para esta práctica cambiaremos nuestra conexión principal al servidor FTP de nuestro anterior equipo a otro distinto, por lo que será necesario cambiar el registro DNS ([[#^c498df]]). También necesitaremos crear un nuevo usuario en nuestra nueva máquina:

```sh
sudo useradd -g www-data -d /var/www/virtual1 -c "Cliente 1" cliente1
```

Es importante recalcar que es imprescindible hacerse con la carpeta de `/var/www/virtual1`, yo lo he hecho con el comando:

```sh
sudo chown  cliente1:www-data /var/www/virtual1 -R
```

La gracia de esta práctica es enlazar los usuarios con relación en lo visto en las [[3.2 Prácticas de HTTP|Prácticas de HTTP]]. También será necesario especificar una contraseña para el "Cliente 1", lo haremos con el comando:

```sh
sudo passwd cliente1
```

Si tras esto nos conectamos al servidor desde un cliente, y capturamos los paquetes con Wireshark, obtendremos lo siguiente:

![[Captura de Wireshark para la conexión FTP.png]]

En este punto, el servidor se comunica mediante el puerto 21 (para el control, para la transferencia se usa el 20) y el cliente desde el puerto 60624.

A continuación, vamos a incluir en el archivo `/etc/vsftpdusers` el nombre del `cliente1` y veremos que ya no nos permite el acceso:

```ftp
Name (ftp.asir21.asir:alumno): cliente1
331 Please specify the password.
Password: 
530 Login incorrect.
ftp: Login failed
```

El comportamiento de `ftpusers` es generalmente privativo, es decir, todos los nombres que se incluyan dentro de la lista no se valorarán para darles acceso. El archivo es manejado por el propio sistema operativo, por lo que no se recomienda su uso. El comportamiento privativo del archivo `vsftpdusers` se puede modificar para que solo los nombres especificados en el archivo puedan iniciar sesión, y el resto no (pasando, por así decirlo, de una lista negra a una lista blanca). Este cambio se puede llegar a cabo especificando lo siguiente en la configuración:

```conf
userlist_enable=YES
userlist_deny=NO
userlist_file=/etc/vsftpdusers
```

Cuando esto sucede, si queremos iniciar sesión con un usuario de que no esté dentro de la lista, saldrá lo siguiente:

```ftp
ftp ftp.asir21.asir
Connected to bookworm21a.asir21.asir.
220 (vsFTPd 3.0.3)
Name (ftp.asir21.asir:alumno): alumno
530 Permission denied.
ftp: Login failed
```

Podría ser problemático que un usuario accediese a la carpeta de otros, por ello debemos encapsular a los usuarios en directorios, para que no puedan salir. Hasta entonces, todas las conexiones se hacen mediante el modo activo donde únicamente se usa un puerto, el 21, para el intercambio y el control de datos. Este modo se puede cambiar haciendo uso del modo pasivo, escribiendo `passive` dentro de la pantalla de FTP.

# Práctica 3: Enjaulamiento (_chroot_)

Puede ser peligroso que los usuarios naveguen por donde no deben. A esto se le llama _chroot_. Por ello, existen 3 directivas encargadas de limitar los accesos:

1. `chroot_local_user`: Si se habilita, todos los usuarios locales únicamente podrán conectarse a sus directorios `home`.
2. `chroot_list_enable`: Establece si se va a usar una lista de nombres a la que aplicar el enjaulamiento.
3. `chroot_list_file`: Establece dónde se ubicará el archivo con los nombres.

Por lo que si queremos que los usuarios locales tengan permisos, necesitaremos activar la primera directiva y esta más:

```conf
allow_writeable_chroot=YES
```

Si habilitamos las 2 últimas directivas, y en el fichero especificado ponemos un usuario concreto, tendremos el siguiente _login_:

```ftp
ftp ftp.asir21.asir
Connected to ftp.asir21.asir.
220 (vsFTPd 3.0.3)
Name (ftp.asir21.asir:alumno):
331 Please specify the password.
Password:
230 Login successful.
Remote system type is UNIX.
Using binary mode to transfer files.
ftp> pwd
Remote directory: /
```

Pone que estamos en la raíz, pero en realidad estamos en nuestra carpeta `home`. 

Con:

```sh
sudo usermod -d /srv/ftp/cliente1 cliente1
```

Podemos cambiar en dónde inician, pues su `$HOME` también cambiará. Es necesario otorgarse permisos.

```ftp
Connected to ftp.asir21.asir.
220 (vsFTPd 3.0.3)
Name (10.0.149.1:alumno): cliente1
331 Please specify the password.
Password: 
230 Login successful.
Remote system type is UNIX.
Using binary mode to transfer files.
```

# Práctica 4: FTPS

Hay 2 formas de hacer este tipo de conexiones:

1. FTPS implícito: En este, el cliente asume  que las conexiones ya son seguras y que van por el puerto 990 (conexión) y 989 (datos).
2. FTPES explícito: El cliente hace la conexión por el puerto 21 y luego es redirigido por el servidor si existe un modo seguro.

Primero, vamos a crear un sitio que use FTP para comprobar posteriormente sus diferencias con FTPS. Crearemos un sitio en FileZilla llamado "NoSSL" y eliminaremos su cifrado (FTP plano). Al hacer la conexión, solo se usa el puerto 21.

Si creamos un sitio llamado "SSL" donde tengamos FTP sobre TLS implícito y nos intentamos conectar, como las conexiones son sobre el puerto 990, si el servidor no las procesa, saltarán estos errores:

![[Problemas con el SSL en FileZilla.png]]

Si queremos que este error no aparezca, tendremos que configurar correctamente el servidor. Para ello, habilitaremos la directiva `ssl_enable`, pero no solo basta con eso: también hay que crear los certificados (autofirmados) con:

![[3.2 Prácticas de HTTP#^142d71]]

Estas rutas deberán ser especificadas en `/etc/vsftpd.conf`. También hay que habilitar las directivas, estas permiten que funcione el modo implícito:

```conf
listen_port=990
implicit_ssl=YES
```

# Práctica 5: Conexión con MySQL

## Configuración de MySQL

Para empezar a cablear todo, necesitaremos instalar algunas herramientas, como `libpam-mysql` con `apt`:

```sh
sudo apt install libpam-mysql
sudo mysql
```

Vamos a crear las tablas, aunque antes de continuar, recomiendo leer la entrada de [[1.3 Gestión de usuarios y permisos en MySQL|Gestión de usuarios y permisos en MySQL]] y [[1.4 Usuarios y permisos de MySQL|Usuarios y permisos de MySQL]]:

```sql
CREATE DATABASE ftp;
USE ftp;

CREATE TABLE usuarios (
	nombre varchar(30) NOT NULL PRIMARY KEY,
	contrasenna varchar(50) NOT NULL
) ENGINE=MYISAM;
```

Y ahora insertamos los datos de los usuarios que puedan acceder, en nuestro caso, será "`virtual1`".

```sql
INSERT INTO usuarios(nombre, contrasenna) VALUES (
	'virtual1', PASSWORD('232425')
);
```

Por último, nos damos permisos para la conexión con vsftpd:

```sql
CREATE USER 'vsftpd'@'localhost' IDENTIFIED BY '123456';
GRANT SELECT ON ftp.usuarios TO 'vsftpd'@'localhost';
FLUSH PRIVILEGES;
```

## Configuración de vsftpd

Añadiremos en nuestro archivo de configuración las siguientes líneas:

```conf
nopriv_user=vsftpd
guest_enable=YES
guest_username=vsftpd # Parece que añadir esta línea es importante para que se puedan crear archivos dentro
user_sub_token=$USER
local_root=/var/www/$USER
hide_ids=YES
log_ftp_protocol=YES
```

También se pueden añadir opciones extra como `virtual_use_local_privs=YES` para que los usuarios virtuales se comporten como locales.

## Configurando los usuarios virtuales

Ahora, modificaremos el archivo `/etc/pam.d/vsftpd`, y añadiremos lo siguiente:

```conf
auth required pam_mysql.so user=vsftpd passwd=123456 host=localhost db=ftp table=usuarios usercolumn=nombre passwdcolumn=contrasenna crypt=2 verbose=1
account required pam_mysql.so user=vsftpd passwd=123456 host=localhost db=ftp table=usuarios usercolumn=nombre passwdcolumn=contrasenna crypt=2 verbose=1
```

Como estas directivas parecen indicadas al azar, podemos recurrir a la [documentación oficial](https://github.com/NigelCunningham/pam-MySQL). Por último, es necesario configurar al usuario "vsftpd":

```sh
sudo useradd -r -d /nonexistent -s /usr/sbin/nologin vsftpd

sudo mkdir -p /var/www/virtual1
sudo chown vsftpd:vsftpd /var/www/ -R
sudo chmod 755 /var/www/ -R

sudo systemctl restart vsftpd.service 
```

## Repaso y ampliación

Este último apartado es extenso, por lo que es probable que una revisión y ampliación ayude a verificar los conocimientos adquiridos.

1. Comprobar información del usuario en MySQL.
	```sql
	USE ftp;
	SELECT * FROM usuarios WHERE nombre = 'virtual1';
	```
2. Comprobar que la contraseña cifrada coincida.
	```sql
	SELECT contrasenna, PASSWORD('232425') FROM usuarios WHERE nombre = 'virtual1';
	```
3. Mostrar los _logs_.
	```sh
	sudo tail -n 200 /var/log/vsftpd.log
	```
4. Mostrar las autenticaciones.
	```sh
	sudo tail -f /var/log/auth.log /var/log/vsftpd.log
	```
