# Gestión y Configuración de bases de datos SQLite

Para el/la (TSR) Administrador de una base de datos SQLite para una pequeña aplicación de gestión de frutas en dispositivos móviles. Tendrás que configurar correctamente la base de datos, optimizar su rendimiento, realizar _backups_/restauraciones y garantizar la seguridad de los datos almacenados.
## Finalidad

1.  Gestionar y configurar el entorno de la base de datos SQLite.
2.  Optimizar el rendimiento de la base de datos a través de diferentes técnicas de ajuste.
3.  Implementar copias de seguridad y restauración.
4.  Aplicar técnicas de seguridad para proteger los datos sensibles.
## Requisitos del entorno

1.  Instalación de SQLite: Asegúrate de tener SQLite instalado en tu entorno de trabajo. Puedes verificarlo con `sqlite3 --version`.
2.  Crea una base de datos llamada `frutitas.db` que almacenará la información de mandarinas, melocotones y caquis ([[DBA_SQLITE_RA12.db|frutitas.db]]).
# Configuración de la base de datos
## Creación de tablas y estructura

Crea las siguientes tablas básicas con las restricciones adecuadas:

1. Mandarinas.
	```SQL
	CREATE TABLE Mandarinas (
		id INTEGER PRIMARY KEY AUTOINCREMENT, -- Identificador único para cada mandarina
		color TEXT NOT NULL, -- Color de la mandarina
		tipo TEXT NOT NULL, -- Tipo de mandarina
		peso INTEGER NOT NULL, -- Peso promedio de la pieza
		fecha_recogida DATE NOT NULL, -- Fecha en la que se recogió la mandarina
		tamaño INTEGER NOT NULL -- Lo grande que es
	);
	```
2. Melocotones.
	```SQL
	CREATE TABLE Melocotones (
	    id INTEGER PRIMARY KEY AUTOINCREMENT, -- Identificador único para cada melocotón
	    tipo TEXT NOT NULL, -- Tipo de melocotón
	    es_suave BOOLEAN NOT NULL -- Indica si el melocotón es suave (1) o (0)
	);
    ```
3. Caquis.
	```SQL
	CREATE TABLE Caquis (
	    id INTEGER PRIMARY KEY AUTOINCREMENT, -- Identificador único para cada caqui
	    id_mandarina INTEGER NOT NULL, -- Relacionado (clave foránea) con la tabla Mandarinas
	    id_melocoton INTEGER NOT NULL, -- Relacionado (clave foránea) con la tabla Melocotones
	    nombre TEXT NOT NULL, -- Nombre del caqui
	    esta_maduro BOOLEAN NOT NULL, -- Indica si el caqui tiene pedigrí (1) o (0)
	    tiempo_maduración INTEGER NOT NULL, -- Tiempo de maduración en días
	    FOREIGN KEY (id_mandarina) REFERENCES Mandarinas(id),
	    FOREIGN KEY (id_melocoton) REFERENCES Melocotones(id)
	);
    ```
## Tamaño y más...

Justifica cuánto ocupa tu base de datos en disco. ¿En qué momento (aumento de tamaño) si se mete más información? ¿Cómo TSR harías para optimizar esto?

```sh
$ du -h DBA_SQLITE_RA12.db
	128K    DBA_SQLITE_RA12.db

$ ls -l | grep DBA_SQLITE_RA12.db                                                                                                         
	-rwxrwx--- 1 root vboxsf 20480 oct 16 14:01 DBA_SQLITE_RA12.db # es decir, 20KB
```

Entiendo que la diferencia entre un tamaño y otro se debe a lo que ocupa en el disco y el tamaño real. Un TSR se debe de hacerse una pregunta muy compleja, hasta qué punto debe de aumentar la eficiencia de las búsquedas a costa del espacio que ocupa el archivo. Un diseño inteligente de la base de datos puede ayudar a que no haya datos repetidos, lo que optimiza el aguardado de datos.

# Copias de seguridad y restauración

1. Realización de una copia de seguridad con el nombre `frutitas_buenas_bonitas.db`.
2. Realiza la restauración desde la copia de seguridad.
3. Automatización de _backups_.

Primero de todo, necesitamos crear un archivo `Bash` que ejecutaremos recurrentemente. Este será: [[copias.sh]].

```sh
$ cat copias.sh

	cp /media/sf_AsirL/2do/ASGBD/Recursos/DBA_SQLITE_RA12.db /media/sf_AsirL/2do/ASGBD/Recursos/frutitas_buenas_bonitas.db
```

Ahora, necesitaremos programar la tarea. Esta parte es un poco compleja, lo primero de todo, hay que darse permisos en `crontab`:

```sh
$ sudo crontab -u $USER -e
	no crontab for marcos - using an empty one
	Select an editor.  To change later, run select-editor again.
	  1. /bin/nano        <---- easiest
	  2. /usr/bin/vim.basic

	Choose 1-3 [1]: 1 # Yo he seleccionado el 1 porque me apaño con nano, pero también está disponible Vim
```

Y escribimos:

```sh

```

A los 59 minutos, a las 23 horas, de todos los días, de todos los meses, y de todos los años, se ejecuta el programa mencionado. Para comprobar que la tarea se ha programador correctamente, ejecutamos:


# Preguntas sin ChatGPT en uso

- ¿Cómo impactan los cambios en el PRAGMA en el rendimiento y la seguridad de la base de datos?
	- El comando `PRAGMA` se encarga de editar las variables de entorno, normalmente más protegidas en el sistema. Estas variables pueden ayudar a modificar parcialmente cómo funciona el programa. Podemos ejecutar el comando `SELECT name FROM pragma_function_list;` para ver la lista completa.
	- Para aumentar la velocidad, podemos usar `PRAGMA synchronous = OFF`, por ejemplo, lo que desactiva las copias de seguridad instantáneas, las que previenen que los datos no se corrompan si se va la luz de repente. Activar esta opción disminuye la seguridad.
	- Por otro lado, aumentar el `cache_size` solo mejora la velocidad de procesamiento.
- ¿Qué mecanismos adicionales usarías para proteger una base de datos SQLite en un entorno de producción?
	- Desde luego, `PRAGMA synchronous = ON`. También se puede añadir módulos a la base de datos, y hacer un control exhaustivo de a qué datos pueden acceder qué usuarios ([[1.2 Práctica de permisos en Linux#^1e7121|Resumen de comandos en Linux]]).
- ¿Qué diferencia existe entre los modos de "`journaling`" como `DELETE`, `TRUNCATE` y `WAL` en SQLite?
	- `PRAGMA journaling` se encarga de establecer qué acciones serias requieren de hacer una copia de seguridad previamente. Por ejemplo, `PRAGMA journaling=WAL` guarda el archivo en una copia temporal y luego lo elimina si se aplica con éxito el nuevo cambio, esto se hace por si es necesario volver a una versión anterior en el caso de que el cambio no surja efecto. Esto se hace por si otra acción de escritura accede al archivo cuando ya se está escribiendo en él. Mientras que en el caso de `TRUNCATE`, en vez de impedir la escritura, trunca las líneas que se han añadido dentro del periodo protegido, y por último, `DELETE` las elimina directamente.
