Esta es la lista de los parámetros se debe incluir dentro del archivo `etc/mysql/my.cnf`, hay más rutas disponibles, pero yo usaré esa.

1. `innodb_buffer_pool_size`: La cantidad de RAM que pueden usar los procesos de InnoDB. Un valor alto agiliza procesos, pero agotará la RAM para otros procesos, mientras que un valor bajo ralentiza las peticiones complejas.
2. `innodb_log_file_size`: Especifica el tamaño que pueden llegar a tener los _logs_. Muy útiles para recuperar datos y solucionar errores. Un valor alto puede saturar el disco.
3. `max_connections`: La cantidad de peticiones que se pueden mantener activas simultáneamente.
4. `query_cache_size`: La cantidad de memoria que se asigna a los resultados de las peticiones. Muy útil para responder rápidamente ciertas peticiones recurrentes.
5. `table_open_cache`: La cantidad de memoria que se guarda de los archivos abiertos recurrentemente. Así, las búsquedas se agilizan pues no es necesario abrir el archivo nuevamente.
6. `tmp_table_size`: La memoria dedicada a la creación de tablas internas temporales, también agiliza las búsquedas, pues si se pide una muy concreta, dicha tabla pedida se cachea, pudiendo acceder más tarde con mayor velocidad. En este caso, no  es necesario hacer la búsqueda nuevamente, basta con acceder a la RAM.
7. `max_heap_table_size`: Dentro de las tablas temporales, establece cuánta memoria puede llegar a ocupar de máximo cada una.
8. `innodb_flush_log_at_trx_commit`: El tiempo que duran las copias de los registros. Como son copias, no es necesario mantenerlas por mucho tiempo, pero un valor muy bajo puede comprometer la integridad de los datos en caso de fallo.
9. `log_bin`: Se encarga de monitorear las acciones de escritura de la base de datos, siendo estas `UPDATE`, `DELETE`, `INSERT`.
10. `slow_query_log`: Establece cuánto pueden llegar a tardar de máximo las peticiones antes de entrar en el registro siguiente.
11. `slow_query_log_file`: El nombre del archivo donde se especificarán qué peticiones no han podido ser resueltas con velocidad.
12. `long_query_time`: El tiempo necesario para que una _query_ sea considerada lenta, y registrada en un archivo como tal.
13. `bind_address`: La IP con la cual se accede a MySQL.
14. `innodb_file_per_table`: Especifica si se creará un archivo por cada tabla o un archivo monolítico único.
15. `performance_schema`: Especifica si se van a recoger datos de rendimiento, prefecto para _debuggear_ en pre-producción.

Esta configuración se aplica en la base de datos que usemos, específicamente esta está pensada para MySQL o MariaDB, y para aplicarla, primero, será necesario instalar los programas si no los tenemos. He aquí una guía detallada: [[1.1.1 Instalación de MariaDB|Instalación de MariaDB]].
