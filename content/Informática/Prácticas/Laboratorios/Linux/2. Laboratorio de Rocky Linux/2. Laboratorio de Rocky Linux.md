# Errores documentados

1. Incidente: No se puede acceder a la página web abierta por Wazuh.
	1. Evidencia: Lo conseguí solucionar antes de capturarlo, pero era un `Conexion refused`.
	2. Causa raíz: El puerto 443 estaba abierto en la configuración, pero esta misma no había recargado, por lo que no se estaba aplicando.
	3. Solución: Tan fácil como ejecutar:
	   ```sh
	   sudo firewall-cmd --reload
	   ```
2. Incidente: Probablemente el GRUB deje de funcionar.
	1. Evidencia: En el final del _script_ `CCN-STIC-610_Protección_de_GRUB.sh` aparece:
	   ```sh
	   # # Regenerar GRUB (Hyper-V)
	   # echo "[*] Regenerando configuración de GRUB..."
	   # GRUB_CFG_PATH="/boot/grub2/grub.cfg"
	   
	   # grub2-mkconfig -o "$GRUB_CFG_PATH" || {
	   #     echo -e "${RED}[ERROR] No se pudo generar el GRUB correctamente.${NC}"
	   #     exit 1
	   # }
	   
	   # chmod 600 "$GRUB_CFG_PATH"
	   ```
	2. Causa raíz: Estoy bastante seguro de que si han tenido que hacer una configuración específica de algo tan delicado como el GRUB para Hyper-V, probablemente haya que activarlo. Digo más, Fernando me dijo que el GRUB fallaba y que hizo otra cosa distinta para solucionarlo, pero a nivel de resultados, eso es equivalente a descomentar las líneas anteriores.
	3. Solución: Descomentar la configuración del GRUB para Hyper-V.
3. Incidente: El _script_ de `CCN-STIC-610_Proteccion_de_GRUB.sh` falla en medio del proceso.
	1. Evidencia:
	   ```sh
	   [*] Detectando tipo de sistema y regenerando configuración de GRUB...
	   + echo '[+] Sistema UEFI detectado.'
	   [+] Sistema UEFI detectado.
	   + GRUB_CFG_PATH=/boot/efi/EFI/rocky/grub.cfg
	   + grub2-mkconfig -o /boot/efi/EFI/rocky/grub.cfg
	   Running `grub2-mkconfig -o /boot/efi/EFI/rocky/grub.cfg' will overwrite the GRUB wrapper.
	   Please run `grub2-mkconfig -o /boot/grub2/grub.cfg' instead to update grub.cfg.
	   GRUB configuration file was not updated.
	   + echo -e '\033[1;31m[ERROR] No se pudo generar el GRUB para UEFI.\033[0m'
	   [ERROR] No se pudo generar el GRUB para UEFI.
	   ```
	1. Causa raíz: El flujo se desvía y acaba intentando proteger el enlace simbólico del GRUB (inaceptable).
	2. Solución: Forzar a que el _script_ ejecute únicamente la regeneración del GRUB para Hyper-V en vez que se vaya por UEFI (caso actual) o BIOS (que no rompería nada, pero es mejor hacerlo bien). Por otro lado, es necesario tener en cuenta que únicamente se pedirá la contraseña para cuando no se acceda al ordenador de forma normal.
4. Incidente: El _script_ de `CCN-STIC-610_Directivas_de_credenciales.sh` no aplica bien las restricciones sobre cómo debe ser una contraseña. Todo esto ya lo vimos en [[1. Laboratorio de Ubuntu#^34c3ab]], por lo que no lo desarrollaré de nuevo.

## Metodología de trabajo

En el fondo, uno se puede ahorrar un poco de trabajo si se da cuenta de que, en muchas ocasiones, los _scripts_ de bastionado para ENS Alto, Difusión Limitada e Información Clasificada son el mismo. Por ello, uno puede crear un pequeño programa en PowerShell para comprobarlo:

```powershell
$carpetaA = "C:\Users\~\Downloads\CCN-STIC 610-25 AnexoA_Rocky_Linux - ENS\ENS ALTO"
$carpetaB = "C:\Users\~\Downloads\DL + IC\INFORMACION CLASIFICADA"
$carpetaC = "C:\Users\~\Downloads\DL + IC\DIFUSION LIMITADA"

function Obtener-Hashes($carpeta) {
    Get-ChildItem $carpeta -File | ForEach-Object {
        $hash = Get-FileHash $_.FullName -Algorithm MD5
        [PSCustomObject]@{
            Nombre = $_.Name
            Hash   = $hash.Hash
            Ruta   = $carpeta
        }
    }
}

$A = Obtener-Hashes $carpetaA
$B = Obtener-Hashes $carpetaB
$C = Obtener-Hashes $carpetaC

$comparacion =
    $A + $B + $C |
    Group-Object Nombre |
    ForEach-Object {
        $grupo = $_.Group

        [PSCustomObject]@{
            Archivo = $_.Name
            Hashes  = ($grupo.Hash -join " | ")
            Coincide = ($grupo.Hash | Select-Object -Unique).Count -eq 1
        }
    }

$comparacion | Format-Table -AutoSize
```

Se puede ir un poco más lejos (modificando el _script_) y llegar a la conclusión de que los ejecutables de ENS Medio y Difusión Limitada son los mismos.

El flujo de trabajo podría ser el siguiente:

1. Crear una máquina.
2. Aplicar los _scripts_ que sean comunes a todos.
3. Exportar el estado actual.
4. Con lo exportado.
	1. Aplicar los programas de Información Clasificada.
5. Aplicar el resto de _scripts_ (de acuerdo con lo que se pide en la de Difusión Limitada).
6. Exportar otra vez el estado actual.
7. Con lo exportado.
	1. Meter el equipo en el dominio (de acuerdo a como se pide en el ENS Medio).

Así se obtienen las 3 máquinas en perfecto estado.

# Función para imprimir resultados y sumar contadores
print_result() {
    local status=$1
    local message=$2
    if [ "$status" -eq 0 ]; then
        echo -e "  ${GREEN}[OK]${NC} $message"
        ((PASS++))
    else
        echo -e "  ${RED}[ERROR]${NC} $message"
        ((FAIL++))
    fi
}

# Verifica si un servicio está activo
check_service() {
    local service=$1
    local desc=$2
    systemctl is-active --quiet "$service"
    print_result $? "$desc (Servicio: $service)"
}

# Verifica si un archivo contiene una expresión regular específica
check_file_regex() {
    local file=$1
    local regex=$2
    local desc=$3
    if [ ! -f "$file" ]; then
        print_result 1 "$desc - ARCHIVO NO ENCONTRADO: $file"
        return
    fi
    grep -E -q "$regex" "$file"
    print_result $? "$desc"
}

# Verifica si el output de un comando contiene una expresión regular
check_cmd_output() {
    local cmd=$1
    local regex=$2
    local desc=$3
    eval "$cmd" 2>/dev/null | grep -E -q "$regex"
    print_result $? "$desc"
}

# Función para verificar puertos/servicios en firewalld
check_firewalld_service() {
    local service=$1
    local desc=$2
    firewall-cmd --list-services 2>/dev/null | grep -q -w "$service"
    print_result $? "$desc"
}

check_firewalld_port() {
    local port=$1
    local desc=$2
    firewall-cmd --list-ports 2>/dev/null | grep -q -w "${port}/tcp"
    print_result $? "$desc"
}

# Función para verificar servicios que deben estar desactivados o no existir
check_disabled_service() {
    local service=$1
    local desc=$2
    local status

    if ! systemctl list-unit-files | grep -qw "${service}"; then
        status="not-found"
    else
        status=$(systemctl is-enabled "$service" 2>/dev/null | head -n 1 | awk '{print $1}')
        if [ -z "$status" ]; then status="disabled"; fi
    fi

    if [[ "$status" == "masked" || "$status" == "not-found" || "$status" == "disabled" ]]; then
        echo -e "  ${GREEN}[OK]${NC} $desc (Estado: $status)"
        ((PASS++))
    else
        echo -e "  ${RED}[ERROR]${NC} $desc requiere atención (Estado: $status)"
        echo -e "${YELLOW}      Tip: Use 'sudo systemctl mask --now $service'${NC}"
        ((FAIL++))
    fi
}

check_service_status() {
    local service=$1
    local expected=$2 # "active" o "masked"
    if [ "$expected" == "active" ]; then
        systemctl is-active --quiet "$service"
        print_result $? "Servicio $service está ACTIVO"
    else
        local status=$(systemctl is-enabled "$service" 2>/dev/null)
        [[ "$status" == "masked" ]]
        print_result $? "Servicio $service está ENMASCARADO"
    fi
}

check_perms() {
    local file=$1
    local perms=$2
    local owner=$3
    if [ ! -e "$file" ]; then
        print_result 1 "Archivo no encontrado: $file"
        return
    fi
    local current_perms=$(stat -c "%a" "$file")
    local current_owner=$(stat -c "%U:%G" "$file")
    
    if [[ "$current_perms" == "$perms" && "$current_owner" == "$owner" ]]; then
        print_result 0 "Permisos/Dueño correctos en $file ($perms, $owner)"
    else
        print_result 1 "Permisos incorrectos en $file (Actual: $current_perms, $current_owner | Esperado: $perms, $owner)"
    fi
}
