# Cliente DDNS

Básicamente, se encarga de monitorear una IP, y cuando esta cambia, le manda un mensaje al DNS avisándole de que debe cambiar sus registros. Supongamos que Juan tiene un servidor de Minecraft llamado `minecraft.asir21.asir`, con un Registro de Recurso `A` que apunta a la IP `172.41.25.99`, entonces, esa IP cambia, el cliente DDNS avisa. DDNS significa, literalmente, DNS Dinámico.

Algunos de estos clientes son No-IP, DynDNS o DuckDNS.

El cliente DDNS se ejecuta normalmente en el router, que soportan bien esta tecnología. O se puede llevar a cabo en el propio servidor DNS o un _host_ a parte que monitorice la IP. En redes más grandes, de este proceso se encarga el DHCP, que monitorea todos los cambios de la IPs y los nuevos clientes, avisando constantemente al DNS.

## Funcionamiento (RFC 2136)

1. Se detecta un cambio en la IP.
2. Preparación del Mensaje de Actualización.
	1. Se comprueba que el registro `A` efectivamente ha cambiado, y que tiene enlazado una fuente (prerrequisitos).
	2. Se ejecutan instrucciones básicas.
		1. Elimina el antiguo registro.
		2. Añadir el nuevo registro.
3. La información de la nueva IP se envía al servidor DNS correspondiente.
4. Por el lado del DNS.
	1. Verifica que el cliente es el adecuado para solicitar un cambio en la IP.
	2. Comprueba los prerrequisitos.
	3. Ejecuta la actualización de la IP.
5. El servidor responde al cliente para notificarle si el cambio ha tenido éxito o no.
6. Si el servidor es primario, y no hay errores, se propaga el cambio al resto de servidores.

# Seguridad en el DNS

Existen 2 tipos de sistemas a la hora de hace el DNS más seguro: DNS sobre TLS y DNS sobre HTTPS.

## DNS sobre TLS (DoT)

El cliente debe de conectarse a un DNS para poder resolver direcciones de internet, pero estas tramas pueden ser interceptadas, por lo que cuando un _host_ descubre un DNS, la primera vez, intercambia información sobre qué protocolos de encriptamiento van a usar, mediante el puerto 853 (TCP). A esto se le llama "_TLS Handshake_".

Se usa el algoritmo negociado de ahora en adelante, y las próximas consultas no requieren esa renegociación.

El cliente autentica la entidad DNS, para asegurarse de que es un servidor legítimo y no un atacante.

### Ventajas e inconvenientes

Evita el espionaje, el _spoofing_ (falsificar tramas), autenticidad, dificulta bloqueos gubernamentales. Pero también es más lento, los administradores de red pueden tener problemas para manejar su propia red, el puerto 883 es fácilmente bloqueable, el DNS externo sigue conservando la información

## DNS sobre HTTPS (DoH)

Encapsula las tramas en tramas HTTPS, lo que le hace contar con cifrado a través del puerto 443, encapsulamiento, respuesta también cifrada, y ocultación del tráfico entre otros paquetes HTTPS.

### Ventajas e inconvenientes

Mejora la privacidad (ni el ISP puede cotillear), mayor seguridad (previene el DNS _spoofing_), puede eludir bloqueos gubernamentales, el puerto 433 no se suele bloquear, por lo que funciona casi siempre. Pero sus inconvenientes son: centralización del tráfico DNS en grandes reenviadores, los administradores de la red pueden tener problemas para manejar nuevas excepciones, mayor latencia, puede eludir configuraciones previas direccionamiento.
