# Configurando Bind9

Sus archivos de configuración se encuentran en las siguientes rutas:

1. `/etc/bind/named.conf`: Configuración principal, incluye otras configuraciones.
	1. Controla el comportamiento y la funcionalidad de Bind9.
	2. Se suele encontrar en `/etc` o `Program files/ISC BIND 9/etc`.
	3. Soporta comentarios que copia de otros lenguajes como C, C++ y Python.
	4. El archivo se valida antes de usarse, por si contiene errores.
2. `/etc/bind/named.conf.local`: Definición de zonas y ajustes locales, establece qué zonas se van a manejar.
3. `/etc/bind/named.conf.options`: Opciones globales de nuestro servidor.

## Manejo de archivos en Bind9

### Sintaxis de los Archivos de Zona

1. Los comentarios empiezan con "`;`", y terminan cuando acabe la línea.
2. Las directivas empiezan con "`$`", y les sigue la instrucción.
3. Los registros de recurso (RR) usan una linea por recurso, y paréntesis en casos excepcionales si la entrada es muy larga
4. Indentation por tabulación o espaciado.

### Archivos de Zona requeridos

1. `root.servers`.
	1. Se usa solo si el servidor soporta consultas recursivas.
	2. Define la lista de servidores raíz (como "a.root-servers.net").
	3. Innecesario en servidores solo autoritativos o en servidores privados.
	4. Bind9 incluye una lista por defecto.
2. `localhost`.
	1. Resuelve a la IP `127.0.0.1`.
	2. Usado por aplicaciones locales (como cuando un servidor SQL se inicia en local).
	3. Es tipo maestro ([[1.1 Servicio DNS#Tipos de servidores]]).
3. `reverse-map`.
	1. Traduce IPs a nombres.
	2. Ausencia de zonas inversas privadas.

### Cláusulas

Las cláusulas pueden ser:

1. Sin `views`.
    1. `ACL` (si se requieren).
    2. `logging`.
    3. `options`.
    4. Otras cláusulas según necesidad.
    5. `zone` (incluyendo las requeridas).
- Con `views`:
    1. `key` (si son necesarias).
    2. `ACL` (si son necesarias).
    3. `logging`.
    4. `options`.
    5. `view` (cada una con sus propias options y zone).

La diferencia entre con `views` y sin `views` radica en si la respuesta es diferente en función de la IP que pregunte.

#### Ejemplos de archivo

Sin `views`:

```conf
acl "trusted" { 192.0.2.0/24; 127.0.0.1; };

options {
    directory "/var/named";
    allow-query { any; };
    recursion yes;
    listen-on { any; };
    // otras opciones...
};

logging { ... };

zone "ejemplo.com" IN {
    type master;
    file "db.ejemplo.com";
    allow-update { none; };
};

zone "2.0.192.in-addr.arpa" IN {
    type master;
    file "db.192.0.2";
};
```

Con `views`:

```
view "internal" {
    match-clients { 192.0.2.0/24; };
    zone "ejemplo.com" {
        type master;
        file "db.ejemplo.com.internal";
    };
};

view "external" {
    match-clients { any; };
    zone "ejemplo.com" {
        type master;
        file "db.ejemplo.com.external";
    };
};
```

# Comandos de testeo

1. `nslookup`.
    1. Formato genérico: ``nslookup [-opt] target [dns] o nslookup [-opt] [-] [dns]``.
    2. `nslookup www.example.com`: buscar un host específico.
    3. `nslookup -type=ANY example.com`: obtener registros MX y NS.
    4. `nslookup -all -type=SOA example.com`: obtener registro SOA y parámetros por defecto.
2. `dig`.
	1. Igual que `nslookup` pero devuelve más información.
3. Con `sudo named-checkzone {nombre de zona} /etc/bind/db.{nombre de zona}.hosts`, se puede comprobar si el archivo está correctamente configurado.
