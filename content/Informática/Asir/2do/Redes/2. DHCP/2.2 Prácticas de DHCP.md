# Práctica 1: Instalación y configuración de Kea

Enlace: [Práctica 1](https://lasalleinstitucion.sallenet.org/mod/book/view.php?id=410354&chapterid=3661).
## Instalación

Para instalar Kea, usamos el comando :

```sh
sudo apt install kea -y
sudo systemctl enable kea-dhcp4-server
sudo systemctl status kea-dhcp4-server
```

Y para revisar la configuración:

```sh
sudo nano /etc/kea/kea-dhcp4.conf
```

## Configuración

Antes de empezar, si hay algo que falla y es necesario acceder a los _logs_ de Kea, se puede ejecutar en la terminal el siguiente comando:

```sh
sudo journalctl -u kea-dhcp4-server -n 50
```

Para este apartado entraremos en la carpeta `/etc/kea/kea-dhcp4.conf`

Después de hacer una copia de seguridad del archivo de configuración, lo cambiaremos enteramente por el siguiente archivo:

```sh
sudo cp kea-dhcp4.conf kea-dhcp4.conf.bak
```

Y en la actual configuración, introduciremos lo siguiente:

```json
{
	"Dhcp4": {
	    "interfaces-config": {
			// Configuración relativa a la interfaz por las cuales Kea va a escuchar
			 "interfaces": ["???"] // enp0s8
			// Se puede configurar el tipo de socket, que por defecto será raw
			// "dhcp-socket-type": "raw"
	    },
	    // Los sockets de control se pueden usar para recargar la configuración
	    // de Kea en tiempo de ejecución, de manera predeterminada se define el siguiente socket de control:
	    "control-socket": {
	        "socket-type": "unix",
	        "socket-name": "/run/kea/kea4-ctrl-socket"
	    },
	    "lease-database": {
			// Indica el sistema de almacenamiento de registros internos, soporta sistemas como mysql y postgresql
	        "type": "memfile",
			// Intervalo en que se simplifica el archivo de concesiones (lease file cleanup)
	        "lfc-interval": 3600
	    },
	    
	    "renew-timer": 90, // T1: El momento en el cual el cliente intenta renovar su IP (normalmente es la mitad de `valid-lifetime`) 
	    "rebind-timer": 100, // T2: El momento en el que, antes de que la IP expire, se mande un mensaje broadcast pidiendo una IP (asumiendo que el servidor DHCP ha fallado)
	    "valid-lifetime": 300, // Duración total de la concesión en segundos
	    "option-data": [
			{
			    //Sustituye por el valor de tu red
			    "name": "domain-name-servers", // Servidores DNS
			    "data": "10.0.XXX.2, 10.0.XXX.1"
			},
			{
				// El 15 hace referencia al "domain-name", es decir, nombre del dominio
				"code": 15,
				//Sustituye por el valor de tu red
				"data": "asir00.asir"
			},
			{
				"name": "domain-search", // Establece una en qué dominios buscar sufijos (equipo.arir21.asir)
				//Sustituye por el valor de tu red
				"data": "asir00.asir"
			},
		    {
				// Se usa para hacer arranques de sistema operativo mediante la red
				"name": "boot-file-name",
				"data": "EST5EDT4\\,M3.2.0/02:00\\,M11.1.0/02:00"
			},
			{
				// Especifica el ttl (Time To Live) predeterminado de los paquetes        
				"name": "default-ip-ttl",
				"data": "0xf0"
			}
	    ],
	    "subnet4": [
	        {
			    "subnet": "10.0.XXX.0/24", // El pool de direcciones que se pueden otorgar será de 20 a partir de la 20
	            "pools": [ { "pool": "10.0.XXX.YY - 10.0.XXX.ZZ" } ],
	            "option-data": [
	                {
					    "name": "routers", // Establece la IP de la Gateway
	                    "data": "10.0.XXX.254" // Sustituye por el valor de tu red, si lo tienes
	                }
	            ]
	        }
	    ],
	    // ¿Qué otras opciones tenemos en cuanto a la depuración y almacenamiento de mensajes?
	    "loggers": [
		    {
		        "name": "kea-dhcp4",
		        "output_options": [
		            {
		                "output": "stdout", // Saca la información a journal
		                "pattern": "%-5p %m\n"
		            }
		        ],
		        "severity": "INFO",
		        "debuglevel": 0 // Este parámetro se puede aumentar para ver más logs
		    }
		]
	}
}
```

# Práctica 2: Configuración de la distribución de IPs

Enlace:  [Práctica 2](https://lasalleinstitucion.sallenet.org/mod/book/view.php?id=410354&chapterid=3669).

## _Host Reservation_

El cliente es autenticado por su dirección MAC, por lo que esta puede ser asignada a un _pool_ específico de direcciones IP:

```json
{
  "Dhcp4": {
    "subnet4": [
      {
        "subnet": "192.168.1.0/24",
        "pools": [
          {
            "pool": "192.168.1.10 - 192.168.1.100" // El Pool dinámico
          }
        ],
        "reservations": [
          {
            // Reserva para una máquina específica (Identificada por MAC)
            "hw-address": "00:1A:2B:3C:4D:5E", // Dirección MAC del cliente
            "ip-address": "192.168.1.50",      // La IP concreta que quieres asignar
            "hostname": "ServidorWeb"          // (Opcional) Nombre de host
          }
        ]
      }
    ]
  }
}
```

O también se puede abstraer la MAC para usar un identificador distinto (`client-id`), más usado para el direccionamiento IPv6:

```json
{
  "Dhcp4": {
    "subnet4": [
      // ... configuración de subred anterior
        "reservations": [
          {
            // Reserva para una máquina específica (Identificada por Client ID)
            "client-id": "01:00:1A:2B:3C:4D:5E", // Client ID en formato hexadecimal (Ejemplo: 01 + MAC)
            "ip-address": "192.168.1.60",       // La IP concreta que quieres asignar
            "hostname": "EstacionTrabajo"
          }
        ]
      }
    ]
  }
}
```

Este mecanismo dota a la IP del equipo específico de prioridad absoluta para configurarse. Si la IP que se define está fuera del _pool_ establecido, entonces, ningún equipo podrá tomarla accidentalmente si el _host_ está fuera de línea. Por lo que una buena práctica es asignas direcciones estáticas fuera del _pool_.

## Clases de cliente (_cliente clases_)

```json
{
  "Dhcp4": {
    "client-classes": [
      {
        "name": "lease-especial",
        "test": "option[61].hw-address == '00:1A:2B:3C:4D:5E'" // Identifica por MAC
      }
    ],
    // ...
  }
}
```

De esta forma, podemos definir al equipo cuya MAC es "00:1A:2B:3C:4D:5E" dentro del grupo "`lease-especial`". A este grupo pueden añadirse clasificaciones y particularidades más adelante. Si se quiere usar `client-identifier` en vez de `hw-address`, se puede cambiar por: `test": "option[61].hex == '01:00:1A:2B:3C:4D:5E'"`.

# Práctica 3: Prioridad en la asignación de IPs

Enlace: [Práctica 3](https://lasalleinstitucion.sallenet.org/mod/book/view.php?id=410354&chapterid=3673).
## Funcionamiento de los rangos y sus propiedades

La configuración sigue un orden creciente, coincidiendo con la generalidad y la especificidad de la configuración:

1. Configuración global: Se aplica a todos los servicios DHCP, y está por encima de `/etc/kea/kea-dhcp4.conf`.
	1. `interfaces`: Interfaces donde Kea va a escuchar.
	2. `dhcp-ddns`: Parámetros relacionados con DDNS ([[1.6 Opciones extras del DNS#Cliente DDNS|Opciones extras del DNS]]).
	3. `control-socket`: Especifica cómo se va a manejar el _socket_.
	4. `loggers`: Cómo se gestionará los _logs_ en Kea.
	5. `lease-database`: Apartados sobre la base de datos a utilizar.
2. Configuración de interfaz: Lo que se especifica en la propia interfaz, ya en el archivo de configuración.
3. Configuración de la subred: Lo que se aplica dentro del apartado `"subnet4": [...]` del archivo de configuración.
	1. `pools`: El rango de la lista de direcciones que usa Kea.
	2. `interface`: Establece, si se puede, la interfaz encargada específicamente de la subred.
	3. `client-classes`: Las clases de cliente que hemos visto antes ([[#Clases de cliente (_cliente clases_)|Clases de cliente]]).
	4. `option-data`: Características de la configuración de global que pueden cambiar para esta subred.
4. Configuración de la clase.
5. Configuración específica de la MAC o la ID de la máquina. ^04970e
	1. `ip-address`: La dirección única y específica para el equipo.
	2. `hw-address`: Su dirección MAC, que servirá como identificador.
	3. `duid`: Identificador único para clientes de IPv6.
	4. `client-id`: El identificador propio del cliente, que es independiente de la MAC, pero que cumple la misma función.
	5. `hostname`: El nombre del _host_, o servicio DDNS utilizado.
## Métodos de distinción entre equipos conocidos y equipos desconocidos

### Reservas de _host_

Uno puede identificar equipos concretos, como ya hemos visto antes ([[#^04970e]]) usando la MAC,el DUID, o estableciendo una IP fija a un cliente concreto, y usar esta misma IP como identificador al no permitir un cambio (aunque si me preguntan, esto es bastante inseguro).

Cualquier cliente que no esté reservado específicamente se considera un equipo desconocido, y se le asignará una IP del _pool_.

### Clases de clientes (de nuevo)

Se puede crear 2 clases, una para los clientes conocidos y otras para los clientes desconocidos. Para esto, podemos ayudarnos de la variable `$know`. Si un equipo no está en ninguna clase, entonces, Kea le asigna internamente el atributo `UNESPECIFIED` o `UNKNOW`. Un ejemplo:

```json
"client-classes": [
    {
        "name": "Clientes_Reservados",
        "test": "member('Clientes_Reservados')" 
        /* Esta clase se usa si el cliente ya está en el sistema de reservas */
    },
    {
        "name": "Mis_Servidores",
        "test": "substring(option[60].hex, 0, 4) == '4d6163'" 
        /* Ejemplo: basar la clasificación en una opción específica enviada por el cliente (vendor-class-identifier) */
    }
]
```
