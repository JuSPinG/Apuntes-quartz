# Métodos de asignación de direcciones IP

1. Asignación estática: Desde el servidor DHCP se configura una serie de parámetros para especificar qué equipos van a tener cuáles IPs específicas. Estas IPs no cambian, por lo que, supongamos, el servidor DNS posee siempre la misma IP, si esto cambiase, habría que reconfigurar múltiples archivos.
2. Asignación dinámica: Dentro de la configuración del servidor DHCP se establecen unos "_pools_" de direcciones, en los cuales se especifican qué rangos de IPs se van a repartir en función de las características del equipo receptor. Se puede configurar, por ejemplo, un _pool_ general en el cual las IPs varíen de la 100 a la 200, pero que si el equipo demandante es un Windows, entonces, que vaya de la 200 a la 240 (por ejemplo).
3. Asignación automática: Una vez que a un equipo se le asigna una IP específica, se la queda para siempre. El servidor DHCP la reserva para que ningún otro _host_ la pueda ocupar.
# Mensajes
## Tipos de mensaje

### Comunes

1. `DHCPDISCOVER`: El cliente, cuando ingresa a la red por primera vez y desconoce los parámetros, recorre toda la red (con un mensaje tipo _broadcast_) en busca de un servidor DHCP. ^1
2. `DHCPOFFER`: El servidor DHCP busca una IP que no tenga asignada y la incluye en el mensaje, el método de búsqueda puede cambiar en función de lo especificado en la configuración. Por último, se envía el mensaje en modo difusión para que el cliente la reciba.
3. `DHCPREQUEST`: El servidor recibe la IP y envía otro mensaje de difusión para indicarle al servidor que acepta la oferta.
4. `DHCPACK`: El servidor DHCP vuelve a comprobar si la IP sigue disponible, registra la  IP como ocupada, y manda toda la información necesaria al cliente para que funcione correctamente en la red, este se configura. Si la IP que se le iba a asignar finalmente le acaba perteneciendo a otra máquina, entonces, el servidor envía un mensaje `DHCPNACK`, y el _host_ vuelve al estado `INIT` y se repite el proceso desde el punto [[#^1|1]].
### No comunes

1. `DHCPDECLINE`: Mensaje enviado por parte del servidor para indicar al servidor que la IP asignada ya está en uso.
2. `DHCPRELEASE`: Mensaje para notificar la liberación de la IP asignada por parte del cliente, y terminar por tanto el alquiler de la misma.
3. `DHCPINFORM`: Mensaje que usa el cliente para consultar los parámetros de configuración local (como el DNS).
4. `DHCPRENEW`: Mensaje para notificar la renovación de la IP asignada durante el tiempo acordado por parte del cliente.
5. `DHCPNAK`: Mensaje del servidor para indicar que la dirección asignada no es válida o que el contrato ha finalizado. Debe volver a comenzar el proceso.

## Comunicaciones
### Caso 1: El equipo se reinicia tras haber adquirido una IP del servidor DHCP

Cuando el equipo ser reinicia, intenta retomar su última dirección IP, por lo que le pregunta a servidor DHCP mediante una petición `REQUEST`. El servidor comprueba si la IP está disponible, y si es cierto, le manda un mensaje ACK para que la empiece a usar. Si la IP está ocupada, el requerimiento será rechazado, obligando al cliente a iniciar de nuevo el proceso de descubrimiento de servidores, como si fuese nuevo en la red. Si el servidor no responde, entonces recupera su antigua IP.
### Caso 2: El servidor DHCP se desconecta

Entonces, el equipo mandará un `DHCPREQUEST`, como de costumbre si su IP va a expirar. Se dará cuenta de que el servidor no responde de vuelta, pero seguirá intentándolo por si acaso. Guarda una pausa de varios segundo y pregunta de nuevo con el `DHCPREQUEST`. Si el servidor responde, entonces volverán a negociar la IP antes de que expire, en caso contario, si la IP del cliente se pierde, entonces, empezará a mandar `DHCPDISCOVER` hasta que el servidor DHCP vuelva.
### Caso 3: La IP del cliente amenaza con expirar

Si una IP se arrenda por X minutos, cerca de la marca X/2, el cliente mandará un `DHCPREQUEST` para saber si puede seguir usando esa IP, el servidor puede responder con un `DHCPACK` (`DHCPRENEWING`) si es así, pero si no, usará un `DHCPDECLINE` de vuelta. Finalmente, cuando la IP expira, el servidor lo indica con un `DHCPRELEASE`.

# Estados del cliente

1. `INIT-REBOOT`: Sucede cuando el cliente se reinicia y comprueba si la IP que ha guardado ha expirado (con `DHCPREQUEST`, y el servidor responde con `DHCPACK`), este estado salta si puede seguir usándola. Algunos sistemas no pueden entrar en este estado porque hacen un `DHCPRELEASE` al apagarse.
2. `INIT`: Sucede  cuando el equipo es nuevo en la red, ha recibido un `DHCPNACK` tras el estado `INIT-REBOOT`, no ha obtenido respuesta del servidor o su "`valid-lifetime`" ha expirado. Repite los mensajes típicos de conexión.
3. `BOUND`: Cuando el cliente ya está correctamente configurado, sin previsiones peliagudas en la proximidad, entrando así en el periodo T0.
4. `RENEWING`: Sucede cuando ya se ha extendido el cliente en el tiempo que marque el "`renew-timer`" de la configuración DHCP, entrando así en el periodo T1.
5. `REBINDING`: Sucede cuando ya se ha extendido el cliente en el tiempo que marque el "`rebind-timer`" de la configuración DHCP, entrando así en el periodo T2. En este estado, envía peticiones de `DHCPREQUEST` en modo _broadcast_ para que cualquier servidor DHCP responda.
