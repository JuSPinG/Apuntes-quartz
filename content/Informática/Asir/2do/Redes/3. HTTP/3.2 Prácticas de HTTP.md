# Práctica 1: Creación de un sitio virtual

## Creación del sitio

Lo primero de todo, debemos añadir un registro `CNAME` en el servidor B para que empezar a virtualizar el servicio HTTP. Así lo pondré en mi caso:

```
virtual1                        IN   CNAME      bookworm21a.asir21.asir.
```

Podemos comprobar que se resuelve correctamente escribiendo:

```sh
$ host -a virtual1.asir21.asir. 10.0.149.2
Trying "virtual1.asir21.asir"
Using domain server:
Name: 10.0.149.2
Address: 10.0.149.2#53
Aliases: 

;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 17942
;; flags: qr aa rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0

;; QUESTION SECTION:
;virtual1.asir21.asir.		IN	ANY

;; ANSWER SECTION:
virtual1.asir21.asir.	604800	IN	CNAME	bookworm21a.asir21.asir.

Received 64 bytes from 10.0.149.2#53 in 4 ms
```

En la carpeta de `sites-available` de Apache, en el servidor A, debemos hacer una copia de `000-default.conf`:

```sh
sudo cp 000-default.conf virtual1.conf
```

```xml
$ cat virtual1.conf # Los comentarios han sido suprimidos
<VirtualHost 10.0.149.1:80>
	ServerName virtual1/asir21.asir

	ServerAdmin webmaster@localhost
	DocumentRoot /var/www/virtual1

	ErrorLog ${APACHE_LOG_DIR}/error.log
	CustomLog ${APACHE_LOG_DIR}/access.log combined

</VirtualHost>
```

Y ahora habrá que crear `/var/www/virtual1/index.html`, y rellenarlo con cualquier cosa. Para habilitar finalmente la configuración, debemos escribir:

```sh
sudo a2ensite virtual1.conf   # Para activar el nuevo sitio
sudo systemctl reload apache2 # Para aplicar cambios
```

## Añadiendo PHP

Debemos instalar PHP con el comando `sudo apt install php`, y a continuación, modificamos nuestra página para poder usar el intérprete:

```php
Sitio virtual 1 desde bookworm21a

<?php
	echo "Muy buenas chavales!";
?>
```

La página se muestra correctamente en http://virtual1.asir21.asir/.

## Añadiendo SSL

Con el comando:

```sh
sudo a2enmod ssl
```

Podemos añadir el módulo SSL para poder añadir dicho cifrado a las páginas web.

Con el comando:

```sh
sudo openssl req -x509 -sha256 -newkey rsa:2048 -keyout /etc/ssl/private/certificate.key -out /etc/ssl/certs/certificate.crt -days 1024 -nodes
sudo chgrp ssl-cert /etc/ssl/private/certificate.key
sudo chmod 640 /etc/ssl/private/certificate.key
```

También, hay que modificar el archivo de `sites-avaliable`, recomiendo copiarlo desde `default-ssl.conf`:

```xml
$ cat sites-available/virtual1SSL.conf 
<VirtualHost *:443>
	ServerAdmin webmaster@localhost
	ServerName virtual1.asir21.asir

	DocumentRoot /var/www/virtual1

	ErrorLog ${APACHE_LOG_DIR}/error.log
	CustomLog ${APACHE_LOG_DIR}/access.log combined

	SSLEngine on

	SSLCertificateFile      /etc/ssl/certs/certificate.crt
	SSLCertificateKeyFile   /etc/ssl/private/certificate.key

	<FilesMatch "\.(?:cgi|shtml|phtml|php)$">
		SSLOptions +StdEnvVars
	</FilesMatch>
	<Directory /usr/lib/cgi-bin>
		SSLOptions +StdEnvVars
	</Directory>

</VirtualHost>
```

Por último, solo es necesario activarlo:

```sh
sudo a2ensite virtual1SSL.conf
sudo systemctl reload apache2
```

`a2ensite` enlaza el archivo de `sites-available` a `sites-enabled`, y en esta carpeta se encuentran los archivos que se leen para ejecución. Igualmente, el archivo que se modifica sigue siendo el de `sites-available`.

# Práctica 2: Permisos en Apache

Si creamos una carpeta llamada `/var/virtual1` y enlazamos nuestro `sites-available/virtual1.conf` a `/var/virtual1/index.html` mediante `DocumentRoot`, nos saldrá un error HTTP 403: Prohibido el acceso. Lo mismo sucede si retornamos a la configuración anterior creamos la carpeta `/var/lib/virtual1/prohibido`, añadimos archivos dentro, y aplicamos la siguiente política en `sites-avaliable/virtual1.conf`:

```xml
<Directory "/var/www/virtual1/prohibido">
	Require all denied
</Directory>
```

Entonces, nos dará el _status code_ de 403.

# Práctica 3: Índices web

Los archivos `index.*` contienen la información que lee el servidor Apache cuando lee el directorio, esto sucede de forma predeterminada. Cuando un cliente entra en un directorio sin archivo `index.*`, muestra el directorio de archivos:

![[Lista de recursos de Apache cuando no existe el index.png]]

Por lo que la práctica consiste en forzar esta directiva, modificando el archivo `sites-available` escribiendo:

```xml
<Directory "/var/www/virtual1/permitido">
	Options -Indexes
</Directory>
```

De esta manera, si uno entra a la ruta `http://virtual1.asir21.asir/permitido/`, le dará la página un error 403, pues los _index_ están deshabilitados. En cambio, si entramos aún así en la ruta `http://virtual1.asir21.asir/permitido/permitido1.html` dará el _status code_ de 200.

Si añadimos la directiva:

```xml
 <Directory "/var/www/virtual1/permitido">
#	Options -Index # Esta la quitamos  
	DirectoryIndex permitido.html
</Directory>
```

El archivo `permitido.html` será el que se establezca como índice sustitutivo.

# Práctica 4: Uso de la directivas de enlace

## `Alias`

El alias es similar a la directiva `CNAME` de [[1.1 Servicio DNS#Registros principales]]. Esta directiva se aplica de la siguiente forma:

```xml
Alias /ruta /var/www/otraruta
```

Con esta directiva se puede acceder fuera de algunos archivos, incluso fuera de `DocumentRoot` y de la IP de la máquina. Es importante recalcar que esta directiva va fuera del apartado `Direcory`.

En nuestro caso, usaremos `/pruebaalias` hacia `/permitido`:

```xml
Alias /pruebaalias /var/www/virtual1/permitido
```

Esto debería funcionar perfectamente.

## `FollowSymLinks`

Siempre existe la posibilidad de que el servidor Apache se encuentre con un enlace simbólico que lleve a otra parte de la máquina, si esto sucede, la seguridad puede verse gravemente afectada. La opción `FollowSymLinks` permite activar o desactivar esta función. Veamos un ejemplos:

```xml
<Directory "/var/www/virtual1/permitido">
	Options -FollowSymLinks
</Directory>
```

## `MultiViews`

Muchas veces sucede que a una páginas web se accede desde distintos navegadores, pero también desde distintos idiomas. Apache soluciona esta variable usando la directiva `MultiViews`. Si, por ejemplo, un usuario español desea ver una página `index` diferente a la de un usuario inglés, se puede añadir la extensión de `index.*.es`, así, Apache muestra una antes que la otra. Esos 2 carácteres del final —"es"— corresponden al _Country Code_.

```xml
<Directory "/var/www/virtual1/permitido">
	Options +MultiViews
</Directory>
```

Así, se establece dinámicamente qué página web se va a mostrar.

## `Redirect`

Esta directiva establece qué redirecciones se harán automáticamente.

```xml
Redirect / https://virtual1.asir21.asir
```

Por ejemplo, esta configuración reenviaría al cliente a la web segura. Como apunte, he descubierto que se produce un fallo de lógica cuando se usa un [[#`Alias`|Alias]].

## `ErrorDocument`

Se pueden crear errores personalizados en Apache (siempre que tengan un _status code_ asociado). Se hace de la siguiente forma:

```xml
ErrorDocument 404 "Página no encontrada"
```

Pero si se quiere, se puede enlazar a una página ya existente:

```xml
ErrorDocument 404 /errors/not_found.html
```

# Práctica 5: Autenticación

## Directivas

Históricamente, se han usado las directivas `Allow`, `Deny` para permitir o denegar ciertos permisos de usuarios. Con la directiva `Order` se especifica en qué orden se resuelven los permisos. Igualmente, estas funciones están deprecadas y serán retiradas en un futuro.

### `Order`

1. `allow, deny`: Primero se aplican los permisos que permiten el acceso, y más tarde se deniegan algunos específicos. Si se cumple una de `deny`, entonces la consulta se cierra.
2. `allow, deny`: Primero se quitan los permisos que permiten el acceso, y más tarde se permiten algunos específicos. Si se cumple una de `allow`, entonces la consulta se aprueba.

### `Allow`

Sus opciones de acceso pueden ser:

1. `from all`: A cualquier acceso del directorio.
2. `from {IP}`: Acceso desde una IP específica.
3. `from {dominio}`: Acceso desde un dominio específico.

### `Deny`

Sus opciones de acceso pueden ser:

1. `from all`: Deniega cualquier acceso al directorio.
2. `from {IP}`: Deniega una IP específica.
3. `from {dominio}`: Deniega un dominio específico.

### Ejemplo de uso

```xml
<Directory /var/www/virtual1/>
	Order deny, allow
	allow from all
</Directory>
```

Hay que recordar que este sistema está completamente obsoleto, en su reemplazo, justo en este ejemplo, se usa:

```xml
<Directory /var/www/virtual1/>
    Require all granted
</Directory>
```
## Creando una autenticación básica

### Para usuarios

Nos situamos en el directorio `/etc/apache2/` y ejecutamos el siguiente comando:

```sh
sudo htpasswd -c usuariosbasic.txt alumno # Quitar el -c si el fichero ya existe
```

Luego nos pedirá una contraseña. Este archivo se puede editar para eliminar o modificar usuarios. Para aplicar la contraseña, aplicamos esto en la configuración del sitio:

```xml
<Directory "/var/www/virtual1/usuarios">
	AuthType Basic
	AuthName "Solo usuarios"
	AuthUserFile "/etc/apache2/usuariosbasic.txt"
	Require valid-user
</Directory>
```

Ahora, cuando entramos al dicha URL, deberemos autenticarnos.

### Para grupos

Podemos cambiar la propiedad `AuthUserFile` por `AuthGroupFile` para que así puedan acceder ciertos grupos. Si aplicamos esta configuración, entonces, también será necesario sustituir la directiva `Require valid-user` por `Require group grupo1` (o cualquier otro grupo).

## Creando una autenticación avanzada (`Disgest0`)

Primero, es necesario habilitar `auth_digest` con:

```sh
sudo a2enmod auth_digest
sudo systemctl restart apache2
```

Y ahora, creamos el fichero de autenticación:

```sh
sudo htdigest -c /etc/apache2/usuarios_d.txt grupo1 usuario1
```

Y la configuración de `Directory` sería la siguiente:

```xml
<Directory "/var/www/virtual1/usuarios">
	AuthType Digest
	AuthName "grupo1"
	AuthUserFile "/etc/apache2/usuarios_d.txt"
	Require valid-user
</Directory>
```

## Preparando la base de datos

Puede ser interesante revisar los apuntes de MySQL/MariaDB de [[Administración de sistemas gestores de bases de datos#^8f4381|Bases de datos]].

Hay que crear la tabla:

```sql
CREATE DATABASE usuarios;
USE DATABASE usuarios;

CREATE TABLE usuarios(
	idusuario INT AUTO_INCREMENT PRIMARY KEY,
	nombreusuario VARCHAR(30) NOT NULL,
	urlusuario VARCHAR(50) NOT NULL
);
```

Ahora, hay que meter algunos usuarios:

```sql
INSERT INTO usuarios(nombreusuario, urlusuario) VALUES
	('alumno', 'https://virtual1.asir21.asir/alumno'),
	('juandi', 'https://virtual1.asir21.asir/juandi'),
	('sanchi', 'https://virtual1.asir21.asir/sanchi'),
	('kwechi', 'https://virtual1.asir21.asir/kwechi'),
	('usuario', 'https://virtual1.asir21.asir/usuario');
```

Ahora hay que darse premisos, de acuerdo con [[1.2 Gestión de usuarios y permisos en MySQL#^1503fb|Gestión de usuarios y permisos en MySQL]].

```sql
CREATE USER 'Apache'@'localhost' IDENTIFIED BY '123456';
```

Y le damos permisos:

```sql
GRANT SELECT ON usuarios.* TO apache@localhost IDENTIFIED BY '123456';
FLUSH PRIVILEGES;
```

### Comprobación de que el usuario funciona

Si iniciamos sesión con él:

```sh
mariadb -u apache -p
```

Y escribimos:

```sql
USE usuarios;

SELECT * FROM usuarios; -- Si funciona, podemos leer
UPDATE usuarios SET nombreusuario = 'Otro' WHERE nombreusuario = 'Alumno'; -- Si funciona, podemos modificar (mal)
```

Y si devuelve:

```sql
ERROR 1142 (42000): UPDATE command denied to user 'apache'@'localhost' for table `usuarios`.`usuarios`
```

Entonces, está bien configurado.

## Configurando la web

Necesitaremos crear un sitio llamado `index.php` con el siguiente contenido:

```php
<?php
    mysqli_report(MYSQLI_REPORT_OFF);

	$host= 'localhost';
	$usuario= 'Apache';
	$password= '123456';
	$bd= 'usuarios';
	$consulta= 'SELECT idusuario, nombreusuario FROM usuarios';

	$conexion= mysqli_connect($host, $usuario, $password);

	if(!$conexion) {
		echo'<li>Conexión fallida con el servidor: ' . mysqli_connect_error() . '</li><br>';
	}
	else {
		echo '<li>Conexión establecida con el servidor.</li><br>';

		$conexionBD= mysqli_select_db($conexion, $bd);

		if(!$conexionBD) {
			echo'<li>Conexión fallida a la base de datos: ' . mysqli_error($conexion) . '</li><br>';
		}
		else {
			echo '<li>Conexión establecida con la base de datos.</li><br>';

			$resultado= mysqli_query($conexion, $consulta);

			if(!$resultado) {
				echo'<li>No se ha podido obtener la consulta: ' . mysqli_error($conexion) . '</li><br>';
			}
			else {
				echo '<li>Consulta ejecutada correctamente.</li><br>';
				echo '<li>Número de registros: ' . mysqli_num_rows($resultado) . '</li><br>';

				while ($fila = mysqli_fetch_array($resultado , MYSQLI_NUM)) {
					printf("ID: %d Usuario: %s <br>", $fila[0], $fila[1]);
				}
                
                		mysqli_free_result($resultado);
			}
		}
        mysqli_close($conexion);
	}
?>
```

Una vez guardado, si accedemos al sitio, nos debería de salir algo como esto:
