# El paso de Web1 a Web2

El paso de Web1 a Web2 supuso un cambio en el dinamismo HTTP. Ya no solo se presenta contenido, sino que también este puede ser distinto para cada persona. Web2 es sinónimo de personalización. [[Implantación de aplicaciones web|PHP]], [[Programación en Python|Python]] (con Flask, aunque se desarrolló más tarde) y Apache cumplen un rol fundamental. Web1 es estatismo, y Web2 es dinamismo.

Algunas tecnologías de Web2 son:

1. [[Implantación de aplicaciones web|PHP]].
2. [[Programación en Python|Python]].
3. Ruby.
4. Node.js
5. Java.
6. C# (.NET).

# Elementos de la URL

La URL (_Uniform Resource Locator_) cuenta con estos parámetros:

1. Esquema/Protocolo: Indica el protocolo que se debe utilizar para acceder al recurso (`http://`, `https://`, `ftp://`).
2. Host/Dominio: El nombre del servidor donde se encuentra el recurso (www.ejemplo.com).
3. Puerto (opcional): El número de puerto en el que el servidor está escuchando. Si no se especifica, se usan los puertos predeterminados para el protocolo (:80 para HTTP, :443 para HTTPS).
4. Ruta/Path: La ubicación específica del recurso dentro del servidor (`/blog/articulo.html`).
5. Parámetros/Query String (opcional): Información adicional que se envía al servidor, generalmente en pares clave-valor después de un ? (`?id=123&categoria=web`).
6. Fragmento/Anchor (opcional): Una referencia a una sección específica dentro del recurso, indicada con un # (`#seccion2`).

# Protocolo HTTP y derivados

1. HTTP (_Hypertext Transfer Protocol_) no requiere presentación (:80).
2. HTTPS, igual, pero seguro (:443).
3. S-HTTP, como HTTPS, pero la seguridad se aplica a los mensajes individuales. No se usa actualmente.

# El servidor virtual

Un servidor virtual es un sistema que le permite a una máquina física alojar varios servidores del mismo tipo. Es decir, la página `asir21.asir` es manejada por el mismo servidor que maneja `infantil15.infantil`. Cada uno posee su propio contenido y configuración.

Existen 4 tipos:

1. _Virtual Host_ basados en nombres: $N$ dominios a una misma IP.
2. _Virtual Hosts_ basados en IP: $N$ dominios a $M$ IPs (poco usado por la escasez de IPv4).
3. _Virtual Hosts_ basados en puertos: $N$ dominios a un mismo puerto (no es lo ideal para el usuario).

Además, un servidor siempre podrá redirigir a otro usando subdirectorios y alias.

# Apache actualmente

En la actualidad, apache funciona con Módulos de Multiplexación de Peticiones (MPMs) como `npm_prefork` y `npm_event`. Se comporta en su conjunto con un demonio que espera hasta que recibe peticiones. Se debe administrar con `systemctl`.

El servidor Apache posee las siguientes configuraciones:

1. Módulos: Para funcionalidades específicas.
2. Directivas de configuración: Para la configuración general.
3. Archivos `.htaccess`: Para la configuración específica de un sitio.
4. _Scripts_ personalizados: Para crear funcionalidades.

Las configuraciones siempre se aplican de lo general a lo particular, siguiendo este orden:

1. Archivo `httpd.conf`.
2. Configuración `<VirtualHost>` del sitio en `sites-available`.
3. Configuración de `<Directory>` (configuración aplicada desde los archivos), `<Location>` (configuración aplicada desde las ubicaciones de la URL) y `<Files>` (configuración aplicada desde unos archivos específicos, donde se admite búsqueda por patrones).
4. Configuración de `.htaccess`, que permite la configuración única del lugar donde se encuentre.

## Conexión persistente

Cuando una conexión entre cliente y servidor se lleva a cabo, cada vez que el cliente cambia de página, refresca, o carga algún contenido nuevo, el servidor tiene que volver a enviar información. Como es TPC, el servidor debe de volver a hacer un _handshake_, por lo que si mantiene la conexión, se ahorra varios pasos, haciendo la conexión más rápida. Con esta técnica, uno se beneficia de tiempos de ejecución y diminución de recursos necesitados.

De forma predeterminada esto está activado. Su directiva de configuración es `KeepAlive On/Off`. Por otro lado, con `MaxKeepAliveRequests` se establece cuántas conexiones abiertas puede haber al mismo tiempo, y `KeepAliveTimeout` especifica por cuánto tiempo se mantienen activas. Una mala gestión de estos parámetros puede llevar a una sobrecarga del servidor.

Este sería un archivo de configuración típico:

```xml
<IfModule mpm_prefork_module>
	StartServers 5
	MinSpareServers 5
	MaxSpareServers 10
	MaxRequestWorkers 150  # Límite máximo de conexiones concurrentes
	MaxConnectionsPerChild 0 # Límite de conexiones hijas por proceso
</IfModule>
```
