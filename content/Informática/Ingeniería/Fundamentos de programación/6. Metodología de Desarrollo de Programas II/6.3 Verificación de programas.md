# 6.3.2 Corrección parcial y total

Enlace: [[Fundamentos de programación.pdf#page=146&selection=522,0,530,5|Fundamentos de programación, página 146]].

Un programa posee 2 formas para indicar si es correcto o no:

- Corrección parcial: si termina con un resultado correcto.
	- Se anota al comienzo y final del programa "*aserciones*" o *asertos* (afirmaciones, formalizadas como expresiones lógicas) correspondientes a las acciones iniciales y al resultado deseado. A la primera se la llama "*precondición*" y a la segunda "*postcondición*", ambas, constituyen una especificación formal del programa.
	- Anotar los puntos intermedios del programa para ver el estado del cómputo.
	- Si se llega a un punto de aserción y luego una de las líneas de ejecución redirige a otra aserción, esta última debe de cumplirse.
	- En [[Python]], una aserción se ve de la siguiente forma:
		- `assert b != 0, "Error: el divisor no puede ser cero" # En el caso de que a sea un dividendo y b un divisor`
- Corrección total: si termina con un resultado correcto y además se valida para cada dato de entrada del programa.
	- Esta se consigue añadiendo una demostración a todos los bucles del programa, en la que estos acaban tras un número finito de repeticiones.

# Enlace: 6.3.5 Razonamiento sobre el esquema: invariante, terminación

Enlace: [[Fundamentos de programación.pdf#page=150&selection=113,0,138,1|Fundamentos de programación, página 150]].

## Invariante

Es necesario demostrar en un bucle `while` que la sentencia es correcta para que se pueda demostrar que el ciclo funciona de forma correcta. A esto se llama *invariante* del bucle. El proceso es el siguiente:

- Antes de que comience el bucle, la invariante es verdadera.
- En cada iteración del bucle, la invariante sigue siendo verdadera.
- Cuando el bucle acaba, la invariante permanece verdadera.

![[Ejemplo razonamiento de diagrama de flujo.png]]

En este caso, el bucle se repite mientras *p* sea correcto, pero *p* no es la invariante. La invariante es una afirmación sobre el estado del programa.

```
n = ... // Número positivo cualquiera
suma = 0
i = 1

while i <= n {
	suma = suma + i
	i = i + 1
}
```

En ese ejemplo, la invariable es que *suma* es la suma de los números enteros del 1 al *i*.

## Variante

La variante, por contra, es el elemento que sí varía y garantiza que el bucle termine. En el ejemplo anterior, la variante es *i*.

Otro ejemplo más:

```c
k = 1;
f = 1;
/*-- INVARIANTE: (k <= n)^(f = k!) --*/
/*-- VARIANTE: n - k --*/
while (k <= n-1) { /* (k > n) = (k <= n-1) */
  /*-- ASERTO: (k <= n)^(f = k!) --*/
  k++:
  /*-- ASERTO: (k <= n)^(f = k!) --*/
  f = f * k;
}
/*-- ASERTO: (k <= n)^(f = k!) → ASERTO: f = n! --*/
```

Este es el desarrollo lógico del proceso matemático es el siguiente:

$$1! = 1$$
$$(k < n) \rightarrow (k + 1 \leqslant n)$$
$$k! = (k - 1)!\cdot k$$
$$(k \leqslant n)\land(k \geqslant n) \rightarrow k = n$$
