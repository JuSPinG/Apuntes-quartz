# 6.4.1 Medidas de eficiencia

Enlace: [[Fundamentos de programación.pdf#page=152&selection=580,0,586,10|Fundamentos de programación, página 152]].

Se define como la cantidad de recursos que se utilizan en la ejecución. Su principal medida es:

- Los tiempos de ejecución.
- La memoria usada.

En muchos casos, ambos factores van relacionados.

Respecto a los tiempos de ejecución, consiguen incrementarse estableciendo un tamaño máximo de variable.

Los tiempos de ejecución van de la mano con la "*complejidad algorítmica*".

# 6.4.2 Análisis de programas

Enlace: [[Fundamentos de programación.pdf#page=153&selection=819,0,827,9|Fundamentos de programación, página 153]].

Para analizar la eficiencia o complejidad del programa, se usan los siguientes datos:

- Cuánto tarde en ejecutarse por cada instrucción básica del lenguaje.
- Cuántas instrucciones de cada clase se realizan durante una ejecución del programa.

A partir de ahí, se puede analizar el tiempo promedio, o el tiempo del caso más pesado. Se usa el segundo criterio, por ser el más sencillo de aplicar:

- La complejidad de un esquema de secuencia en función de las acciones compuestas.
- La complejidad de un esquema de iteración se obtiene sumando la serie correspondiente al número de instrucciones en las repeticiones sucesivas.

Supongamos el siguiente código:

```c
maximo = a;

if (a > b) {
  maximo = b;
}
```

Y ahora, hay que dar cuenta del número de instrucciones que se dan:

- Operadores aritméticos (+, -, \*...).
- Controladores de flujo o "decisiones" (`if`, `else`, `while`).

```c
maximo = a; /* Número de instrucciones: 1 */

if (a > b) { /* Número de instrucciones: 3 */
  maximo = b; /* Número de instrucciones: 3 - 4 */
}
```

Hay que recordar que siempre hay que ponerse en lo peor, por lo que el total de número de instrucciones ejecutadas es 4.

Este caso es sencillo porque la complejidad es fija, constante, pero no suele ser así:

```c
k = 1;                  /* Número de instrucciones: 1 */
f = 1;                  /* Número de instrucciones: 1 */
while (k < n) {         /* Número de instrucciones: 2 */
  k++;                  /* Número de instrucciones: 1 */
  f = f * k;            /* Número de instrucciones: 2 */
}                       /* Número de instrucciones: El bucle cierra en función de n, 5(n-1) */
```

Lo que daría la función $5n - 3$.

# 6.4.3 Crecimiento asintótico

Enlace: [[Fundamentos de programación.pdf#page=155&selection=306,0,319,3|Fundamentos de programación, página 155]].

El crecimiento de la complejidad de un programa se puede disparar fácilmente si depende de N y N se eleva en exceso. Imagine el lector la diferencia entre $100N$ y $N^2$ ante un valor de N elevado. Por esto, hay que tener en cuenta el comportamiento asintótico. El "*Big O*".

La forma en la que una función crece para tamaños grandes, describe su comportamiento asintótico, que se representa mediante la notación:

$$O(f(n))$$

He aquí unos ejemplos de formas de crecimiento:

|        O-grande        |           Complejidad           |
| :--------------------: | :-----------------------------: |
|         $O(k)$         |        Constante, ideal         |
|    $O(log\cdot n)$     |   Logarítmica, muy eficiente    |
|         $O(n)$         |      Lineal, muy eficiente      |
| $O(n\cdot log\cdot n)$ |  Lineal-logarítmica, eficiente  |
|        $O(n^2)$        |   Cuadrática, menos eficiente   |
|        $O(n^k)$        |   Polinómica, poco eficiente    |
|        $O(k^n)$        | Exponencial, muy poco eficiente |

Aunque siempre se intenta evitar la creación de un programa ineficiente, no siempre se puede, hay veces en las que comparar 2 listas no se puede hacer de forma más rápida que anidando un `for` en un `for`.
