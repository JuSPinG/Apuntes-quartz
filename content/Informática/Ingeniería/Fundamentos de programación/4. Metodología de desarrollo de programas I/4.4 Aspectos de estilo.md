# 4.4.2 Comentarios. Documentación del refinamiento

Enlace: [[Fundamentos de programación.pdf#page=92&selection=433,1,461,3|Fundamentos de programación, página 92]].

Aunque de forma restrictiva, solo es posible poner comentarios usando `/*` y `*/`, es importante aclarar que hacia qué va dirigido dicho comentario puede variar.

## Cabecera de programa

Tiene como finalidad documentar el programa de forma general, dotándolo de identificación, finalidad, descripción general...

```c
/***************************************************************
* Programa: Silla.
*
* Autor: Marcos Ndah.
* 
* Descripción:
*     Este programa imprime de forma esquemática la silueta
*     de una sillausando caracteres normales de la impresora.
***************************************************************
```

Esta sería la descripción general, junto con algunos datos extra.

## Cabecera de sección

Por otro lado están las cabeceras:

```
/*==================================
    Parte ejecutable del programa
==================================*/
```

## Comentarios-orden

Se añaden para hablar sobre una orden intermedia, es de gran valor, sobre todo si se pretende modificar el código más tarde.

```c
/*-- Imrpimir el respaldo --*/ {
  printf("!\n");
  printf("!\n");
}
```

Además, se suele usar el `/*--` para abrir, y el `--*/` para cerrar.

## Comentarios al margen

Se sitúan a la derecha de la instrucción, en la misma línea de la que se quiera especificar algo. Es importante establecerlos en una posición fija, todos los inicios de comentario alineados:

```c
float base, altura;  /* Dimensiones en cm */
float area;          /* Área en cm^2 */
int volumen;         /* Volumen en litros */
```

## En resumen

Un código muy comentario (en este caso tanto, que se vuelve innecesario para lo simple que es este código), debería de contar con esto mismo:

```c
/***************************************************************
* Programa: Silla.
*
* Autor: Marcos Ndah.
* 
* Descripción:
*     Este programa imprime de forma esquemática la silueta
*     de una sillausando caracteres normales de la impresora.
***************************************************************

/*==================================
    DIRECTIVA DE COMPILACIÓN
==================================*/
#include<stdio.h>

/*==================================
    Parte ejecutable del programa
==================================*/
int main() {
  /*-- Imprimir el respaldo --*/ {
    printf("!\n");
    printf("!\n");
  }
  /*-- Imprimir el asiento --*/ {
    printf("======\n");
    printf("!\n");
  }
  /*-- Imprimir las patas --*/ {
    printf("!     !\n");
    printf("!     !\n");
  }
}
```
# 4.4.3 Elección de nombres

Enlace: [[Fundamentos de programación.pdf#page=96&selection=7,0,15,2|Fundamentos de programación, página 96]].

Otra parte importante del código. Los nombres que inventa el programador deben de tener un sentido nemotécnico, de manera que recuerden fácilmente lo que quieren decir.

No es lo mismo nombrar a las variables `int x, y, z;` que `int base, altura, area;`. Los valores constantes y variables deben de ser designadas mediante sustantivos y las acciones, como los procedimientos, como verbos. Además, dichos verbos se suelen usar en infinitivo.
# 4.4.4 Uso de letras mayúsculas y minúsculas

Enlace: [[Fundamentos de programación.pdf#page=99&selection=6,0,18,10|Fundamentos de programación, página 99]].

Hay cierto estándar a la hora de crear nombres de tipos, procedimientos y funciones, estos, siempre empiezan por mayúscula. Por otro lado, los nombres de variables y constantes empiezan por minúscula, y si son compuestas, se usa camel-case.

# 4.4.5 Constantes con nombre

Enlace: [[Fundamentos de programación.pdf#page=100&selection=78,0,84,6|Fundamentos de programación, página 100]].

El uso de constantes puede ser muy conveniente, sobre todo para declarar, por ejemplo, valores de conversión, como de toneladas a gramos, o de centímetros a pulgadas. Así, en vez de recordar la cantidad, solo se necesita usar el nombre.

Por otro lado, puede ser interesante cambiar los valores constantes en un futuro, a estas constantes se las llama "parámetros del programa", y suelen destacar, muy a menudo en mayúscula todo.
