# 8.1.1 Especificación y realización

Enlace: [[Fundamentos de programación.pdf#page=192&selection=4,0,16,8|Fundamentos de programación, página 192]].

A la hora de crear un programa, es esencial definir 2 posibles visiones: la abstracta o la simplificada, y la visión detallada.

- La visión abstracta trata el «qué» hace dicha operación. Se resume como la interfaz (invocar) de operación. Establece la sintaxis.
- La visión detallada trata el «cómo» se hace dicha operación, y permite que el procesador la ejecute. Se resume como la realización, implementación o ejecución de la operación. Establece la semántica.

```c
int Maximo(int a, int b) {                           /* Especificación sintáctica */
  /* Maximo(a, b) es el máximo de a y b */           /* Especificación semántica  */

  if (a > b) {                                       /* Realización */
    return a;
  } else {
    return b;
  }
}
```

Una vez invocada, no importa cómo funcione `Maximo`, solo necesitamos saber la especificación. El bloque de `Maximo` puede cambiarse a cualquier otro algoritmo, mientras siga conservando la misma funcionalidad. Por ello se dice que la especificación es una idea abstracta en programación, porque el bloque queda abstraído en la cabecera.

$$Maximo(a, b)=(a\geq b \rightarrow a|b)$$

Como ver ese trozo logico-matemático puede ser confuso, es necesario usar los términos "Precondición" y "Postcondición" para ayudar a leer al programador:

```c
int Maximo(int a, int b) {
  /* 
    PRE:
    POST: Maximo(a, b) es el Máximo de a y b
    POST: Maximo(a, b) = (a >= b → a|b)
  */

  if (a > b) {
    return a;
  } else {
    return b;
  }
}
```

La precondición está vacía porque se asume que es siempre cierta, pues la función devuelve el valor máximo siempre.
# 8.1.2 Funciones. Argumentos

Enlace: [[Fundamentos de programación.pdf#page=194&selection=134,0,138,10|Fundamentos de programación, página 194]].

Para, por ejemplo, elevar al cubo una variable, es necesaria una pequeña capa de abstracción.

```c
float Cubo(float z) {
  /*
    PRE: 
    POST: Cubo(z) = z^3
  */
  ...
}
```

O:

```c
float Cubo(float z) { /* Especificación sintáctica */
  /* Cubo(z) = z^3 */ /* Especificación semántica  */
  ...
}
```

Siempre que se cumpla lo especificado, la función `Cubo` cumple correctamente con su nivel de abstracción.

Por otro lado, la realización es tan sencilla como la siguiente:

```c
float Cubo(float z) {
  return z * z * z;
}
```

O tan sofisticada como la siguiente:

```c
float Cubo(float z) {
  float c = 1.0;

  for (int k = 1; k <= 3; k++) {
    c = c * z;
  }
  return c;
}
```
# 8.1.3 Acciones abstractas. Procedimientos

Enlace: [[Fundamentos de programación.pdf#page=196&selection=153,0,165,1|Fundamentos de programación, página 196]].

Al igual que las funciones pueden ser algo abstractas, a los procedimientos les pasa lo mismo. Por esto, se pueden tener 2 versiones de un procedimiento. La primera es la visión abstracta o específica, formada por la cabecera del procedimiento - el «qué» hace - mientras la segunda, consiste en su realización - el cómo - . Ejemplo para intercambiar 2 variables:

```c
void Intercambiar(int & a, int & b) {
  /*
    PRE: 
    POST: (a', b') = (b, a)
  */

  int aux;

  aux = a;
  a = b;
  b = aux;
}
```

A partir de aquí, podemos implementar dicho procedimiento de la siguiente manera:

```c
if (p > q) {
  Intercambiar(p, q);
}
```

Es normal que los procedimientos usen argumentos pasados por referencia. Lo que no quita que siga siendo recomendable el uso de procedimientos puros, de tal forma que sigue siendo necesario que no produzcan efectos secundarios.
