Un "*subprograma*" se define como una parte del programa que se desarrolla por separado (literalmente, una función o una librería, aunque parece que ahora se llama procedimiento) y se invoca mediante un nombre simbólico. Si un programa sirve para resolver un problema, un programa sirve para resolver un *subproblema*.

El uso de subprogramas se vuelve esencial en los siguiente contextos:

- En programas muy complejos: Así, se estructura mejor un programa entre tantas operaciones.
- Cuando se repiten operaciones análogas: Así, se ahorra código, se menciona dicho nombre simbólico las veces que haga falta en vez de copiar y pegar el trozo completo.

La técnica de [[4.3 Desarrollo por refinamientos sucesivos|refinamientos sucesivos]] sugiere la mayor descomposición posible, pero ahora ya no es necesario, pues ahora se pueden descomponer el problema hasta llegar a una función que se pueda definir y reutilizar. He aquí un ejemplo:

- Calcular e imprimir el perímetro →
	- Leer las coordenadas de los vértices →
		- Leer las coordenadas del punto A.
		- Leer las coordenadas del punto B.
		- Leer las coordenadas del punto C.
	- Calcular el perímetro.
	- Imprimir el perímetro.

La cosa es que, como hay que leer coordenadas varias veces, es útil no andar copiando y pegando código de más, si se puede usar una función, claro.

```c
#include<stdio.h>
...
void LeerVertices() {
  LeerCoordenadas(A);
  LeerCoordenadas(B);
  LeerCoordenadas(C);
}

void CalcularPermetri() {
  ...
}

void ImprimirPerimetro() {
  ...
}

int main() {
  LeerVertices();
  CalcularPerimetro();
  ImprimirPerimetro();
}
```

Donde se definen las funciones se llama cabecera, luego, lo que hay entre corchetes se llama bloque de código.
