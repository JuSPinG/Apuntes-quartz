# 7.7.1 Uso de variables globales. Efectos secundarios.

Enlace: [[Fundamentos de programación.pdf#page=179&selection=77,0,89,11|Fundamentos de programación, página 179]].

El nombre de una variable debe de ser lo suficientemente claro para que cuando se le introduzcan X argumentos, el programador pueda intuir Y respuesta con tan solo el nombre de la función. Es muy importante ser claros con esto, porque, si por algún casual, una función modifica una variable global del programa, puede suceder cualquier cosa, los llamados "efectos secundarios", por eso es importante tenerlo todo bien instanciadito. He aquí una lista de cómo evitar efectos secundarios:

- Una función no puede modificar variables globales.
- Una función no puede devolver datos de un tipo contrario a su definición.
- Su nombre debe de dar una descripción muy fiel de a qué se dedica.

Si cumple las 2 primeras, se dice que es una función pura.

Aunque es una forma de meter la gamba, en algunos casos, se pueden usar funciones de la siguiente manera:

```c
float base, altura;
...
float AreaRectangulo() {
  return base * altura;
}
...
```

Además, no cuesta nada cambiarlo a:

```c
float AreaRectangulo(float base, float altura) {
  return base * altura;
}
...
```

Si se van a usar todo el rato los mismos argumentos, uno se puede llegar a saltar la transparencia referencial, sobre todo si se va a trabajar antes y después con el valor de una o más variables (normalmente bajo la misma función).

```c
void Acumular(float &suma, float valor) {
  suma += valor;
}
...
float total;
...
total = 0;
Acumular(total, 3.5);
Acumular(total, 0.2);
Acumular(total, 2.7);
Acumular(total, 1.5);
printf("%d", total);
```

Esto se podría acortar a:

```c
float total;
...
void Acumular(float valor) {
  total += valor;
}
...
total = 0;
Acumular(total, 3.5);
Acumular(total, 0.2);
Acumular(total, 2.7);
Acumular(total, 1.5);
printf("%d", total);
```
