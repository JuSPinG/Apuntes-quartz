# 15.2.1 Proceso de compilación simple

Enlace: [[Fundamentos de programación.pdf#page=414&selection=195,0,213,1|Fundamentos de programación, página 414]].

Un fichero fuente es un fichero de texto que contiene el código de una unidad de compilación, es decir, es posible compilar. La compilación de un fichero fuente produce un fichero objeto (`.o`) que contiene la traducción del código a instrucciones máquina (similar a la JVM), mientras que el fichero fuente siempre tiene la extensión `.cpp`:

- HolaMundo.cpp
	- Compilador.
- HolaMundo.o
	- Montador.
- HolaMundo.exe

# 15.2.3 Módulos no principales

Enlace: [[Fundamentos de programación.pdf#page=415&selection=378,0,386,1|Fundamentos de programación, página 415]]

Los elementos de los módulos no principales están destinados a ser usados por un programa principal.

Se distinguen 2 tipos de elementos:

- Elementos públicos: Deben de ser visibles para el programa principal.
- Elementos privados: Deben de ser visibles para el propio módulo.

También destaca la diferencia entre el fichero cabecera o fichero interfaz, y el fichero de implementación. El primero se vería de la siguiente forma:

```c
/*****************************************************
* Interfaz de módulo: Tabulación
*
* Descripción:
*   Este módulo contiene los elementos para
*   imprimir series de números en varias columnas
******************************************************/
#pragma once

extern int numColumnas; /* Número de columnas */
extern int anchoCoumna; /* Ancho de cada una */

/*-- Iniciar la impresión --*/
void Iniciar(char titulo[]);

/*-- Imprime un número, tabulando --*/
void Imprimir(int numero);

/* Completa la impresión de la última línea */
void Terminar();
```

Mientras que el fichero de implementación se ve de la siguiente forma:

```c
/*****************************************************
* Módulo: Tabulación
*
* Descripción:
*   Este módulo contiene los elementos para
*   imprimir series de números en varias columnas
******************************************************/
#include<stdio.h>
#include<string.h>
#include "Tabulacion.h"

int numColumnas = 4;
int anchoColumna = 10;

static int columna = 1;

/*-- Iniciar la impresión --*/
void Iniciar(char titulo[]) {
  Terminar();
  printf("%s\n", titulo);
  columna = 1;
}

/*-- Imprime un número, tabulando --*/
void Imprimir(int numero) {
  if (columna > numColumna) {
    printf("\n");
    columna = 1;
  }
  printf("%*d", anchoColumna, numero);
  columna++;
}

/* Completa la impresión de la última línea */
void Terminar() {
  if (columna > 1) {
    printf("\n");
  }
  columna = 1;
}
```

Cabe destacar que la interfaz debe de usar la extensión `.h`, mientras que la implementación, debe de usar `.cpp`. En uno se declaran elementos, y en el otro se definen.

# 15.2.5 Declaración y definición de elementos públicos

Enlace: [[Fundamentos de programación.pdf#page=419&selection=170,0,186,8|Fundamentos de programación, página 419]].

Es importante hacer énfasis en las diferencias entre declarar elementos y definirlos, por ello, se presenta la siguiente tabla:

| Declaración (fichero.h)      | Definición (fichero.cpp)         |
| ---------------------------- | -------------------------------- |
| `typedef ... T_Nuevo ...;`   | No aplica                        |
| `const T_Constante = valor;` | No aplica                        |
| `extern Tipo variable;`      | `Tipo variable = valor;`         |
| `Tipo Subprograma(args);`    | `Tipo Subprograma(args) { ... }` |
# 15.2.6 Conflicto de nombres en el ámbito global

Enlace: [[Fundamentos de programación.pdf#page=420&selection=519,0,533,6|Fundamentos de programación, página 420]].

Si un programa principal usa 2 módulos que usen el mismo nombre para una sentencia dada, entonces, al intentar compilar el programa, habrá errores. Por ello, se usa algo similar a lo que se utiliza en [[Python]]: introducir un prefijo extra que guarde relación el nombre del módulo del que proviene.

Por otro lado, usando la palabra reservada `static`, se establece que el elemento declarado solo puede ser usado por los elementos del propio módulo.

# 15.2.7 Unidades de compilación en C±

Enlace: [[Fundamentos de programación.pdf#page=422&selection=60,0,82,2|Fundamentos de programación, página 422]].

En un programa que usa módulos, siempre se tiene una estructura similar a la siguiente:

- Módulo principal: `programa.cpp`.
- El fichero de interfaz de un módulo: `modulo.h`.
- Fichero de implementación de un módulo: `modulo.cpp`.

Cabe recalcar que los ficheros de interfaz no pueden ser compilados como tal, pues no poseen convertibilidad a tipo objeto. Más bien, se compilan implícitamente cuando el programa principal realiza la llamada con `#include`.

# 15.2.8 Compilación de programas modulares. Proyectos

Enlace: [[Fundamentos de programación.pdf#page=423&selection=171,0,187,9|Fundamentos de programación, página 423]].

Se supone un programa con la siguiente estructura:

![[Compilación de programas modulares.png]]

Entonces, `Tabulacion.h` queda implícito tanto en `Serie.cpp` como en `Tabulacion.cpp`.

Este es el siguiente proceso de compilación:

- Compilar los módulos uno a uno.
- Montar el programa ejecutable combinando todos los ficheros objeto de los módulos.

Las nuevas tecnologías de desarrollo de programas permiten una recompilación más simple cuando no todos los ficheros han sido editados. A esto se le conoce como proyectos, y necesita una información mínima:

- Obligatorios:
	- Nombre del proyecto.
	- Lista de ficheros fuente de implementación.
- Opcionales:
	- Lista de ficheros de interfaz.
	- Forma de invocar al compilador, con opciones particulares (las *flags* de toda la vida) de ese proyecto.
